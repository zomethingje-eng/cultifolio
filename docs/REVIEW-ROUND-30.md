## The salvage rule, rebuilt

Round twenty-nine made a value of the wrong type a per-change drop and added closed word lists for a few fields. Two things were wrong with that.

1. **A dropped required field could leave a half-made live record** (R1-1; the reviewer's one thing to fix). A new plant whose `taxonName` was unreadable but whose `acc` and `status` were fine folded as a live plant with no name, and the plants page threw on it. Every kind now has its required fields (a plant's name and status, a batch's name, method, date, count and status, a place's name, an event's plant, day and type, a photograph's day and size, a species record's name); a change to one of these that cannot be read takes every change to that record in the same list with it, and says so, so a new record is never made half and a record already here keeps what it had. Unit test: the three-change plant folds to nothing; a plant beside it with a numeric note folds with the note as text.
2. **A word outside the new lists was dropped for good on every other device** (R2-1; the reviewer's one thing to fix, and reproduced with two devices). A pull dropped the change, folded the rest of the batch and moved on, so a status a newer build wrote ("sold", the next feature) would never reach a device on this build, even after it upgraded; and the v2 importer had written "leaf cutting" and "Wild collected" before round twenty-eight, which every peer was now dropping. Three changes. A word this build does not know folds as it is and is shown by its word (the propagation pages show an unknown method's word rather than "Seed"; an unknown status shows under All with its word), which is how an event's type always worked; the lists guard the forms and the importer, where a value starts, and nothing else. The old importer's words are mended wherever the log is read: a method by the word in it ("leaf cutting" is leaf, "stem cutting" is cutting), a free-text provenance to the nearest of the five ("Wild collected" is wild, "ex habitat" is f1, anything unplaceable is unknown). And a batch with anything in it this build cannot read is set aside whole, under its name, for a later build to read again, as a batch with a bad stamp always was: folding the rest and moving the cursor past it is what lost the change. Unit tests for each, and a two-device engine test: the bad batch is quarantined with nothing of it applied, the good one folds "sold" and mends "leaf cutting".
3. **The push path was not mended** (R2-5). Changes read for a push came straight from the store, so a numeric price still travelled. Mended there too.

## Records lost or wrong

4. **A full device between a photograph's pixels and its record left the pixels behind** (R1-2). The record write is wrapped: if it fails, the pixels come out again and the error stands. The id is fresh, so nothing older can be touched. Unit test against a vault that refuses the record.
5. **A merge restore that failed after its records were stored deleted their pixels** (R2-2). The ingest is not one write (the changes, then the import-day stamps), so round twenty-nine's cleanup could take out pixels whose records had landed. Only the pixels of records not live afterwards are removed.
6. **Photo Undo put the cover back over a later choice** (R2-3, part). The cover is restored only when nothing has been chosen since. Unit test. The other part, a second removal within eight seconds replacing the first's Undo, is deferred: the fix is a grace period in the store rather than in the toast, and it goes with the log editor.
7. **The pot guard checked the entry's own day only** (R2-4). A loss dated before a potting that emptied the pot passed. A new potting or loss must fit on its own day and on every later day something was potted or lost, the check the count-removal guard already ran.

8. **The reader capped each entry but not the total** (R2-7). Ten entries each under the cap added up to two gigabytes. The sum of declared sizes is bounded by the file's own size (JPEGs are stored, so a backup inflates to little more than itself) and `changes.json` by its own cap, both at the table of contents. Test.
9. **`cutBefore` and two tabs whose pairs interleave** (R2-6): confirmed, and deferred as the reviewer suggests. The only full answer is a base inside the notes value, which is a format change; the cost meanwhile is a false "notes replaced" line, never lost text.
10. **The release suite failed for four evening hours** (R1-3). Two tests built "yesterday" and "today" with `toISOString()`, which is UTC; the app dates things on the local calendar, and from 20:00 in the Americas the two disagreed. The tests use a local-calendar day now.

## The species reference

11. **Old names led nowhere** (R2-8; the reviewer's most likely first complaint from this audience). A label or a seed list says Haworthia attenuata; the reference files the species under the name the backbone accepts, and the address said "not on it". When no dossier answers to a slug, the Worker now asks the backbone's match service whether the name is a synonym; if the accepted species is in the reference, the page sends the reader there with a line saying so ("Haworthia attenuata is a synonym: the GBIF backbone accepts this species as Haworthiopsis attenuata"), and if it is not, the 404 says what the name is now. The question goes from the server, only for an address the reference does not hold, and the answer is cached at the edge for a day; the privacy section says so. Unit tests; the live check asks for `/species/haworthia-attenuata` and expects the redirect. Folding synonyms into the search index needs the index rebuilt, which is the corpus tooling's; the six names the reviewer's fetch reported as missing should be checked against the index when that runs.
12. **"Cold floor" is one cell's figure** (R2-9). The card says it is the typical site's now, and shows the range's coldest mean night beside it, which was already computed. Skipping cells that are mostly sea is a build-time change and is noted for the next corpus build.
13. **Photographs with no cultivated flag were captioned "observed growing wild"** (R2-12). Commons and GBIF media carry no flag; the caption says wild only when a source says so, and nothing when none does. The GBIF media query now leaves preserved specimens out, as the bulk path did. A photograph outside the native range is not flagged yet.
14. **Records with no stated accuracy counted as precise** (R2-11). One line used `?? 0` where the de-duplication four lines up used `?? Infinity`. A record with no figure enters the climate now only as a human observation with coordinates to three decimals or better. Unit test. Takes effect at the next corpus build.
15. **The dossier schema still carried a `note` field with a `model` attribute** (R2-13). Nothing wrote or rendered it; under the rules it should not exist. Gone from the schema.
