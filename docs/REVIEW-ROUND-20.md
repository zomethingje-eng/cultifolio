# Review round twenty: two reviews of `6be76ff`, triaged

The first reviewer's round nineteen (fourteen findings, three readers: sync and the server, UI and routing, the formats page and the public claims) and the second reviewer's eleventh pass (two findings, one shared, and four design recommendations). Every finding was checked in the source; all are real and all sixteen are done, with two of the design recommendations taken and two deferred. Both reviewers put the same thing first: the service worker did not know the renamed paths. "R1-n" is the first review's numbering, "R2-n" the second's.

## Privacy and blocked flows

1. **An old bookmark sent its record id to the server, and offline it failed outright** (R1-1, R2-2; both reviewers' one thing to fix). Round nineteen's 301s were in the server hook only; the worker's shell match knew the new paths alone, so `/benches/<id>?edit=1` went to the network before the redirect, carrying the id round sixteen said never leaves the device, and offline an installed app got the browser's error page. The worker now carries the same `MOVED` map as the hook and answers the redirect itself, query kept, before anything is fetched; the new path is then a shell like any other. e2e: with the worker controlling the page and a context route standing in for the server, `/benches/k1?edit=1` lands on `/places/k1?edit=1` rendered from the vault and `/sowings/new?loc=k1` on `/propagation/new?loc=k1`, and the stand-in server is never reached.
2. **A stale run's push answered 429 went on to pull the new vault** (R1-2; a gap in round eighteen's fix). `run()` caught the push's "wait" so the pull could still happen, and `pull()` read `this.meta` afresh: after "Stop syncing" that was null, so the run set "Checking for changes…" on a stopped device and died in a TypeError with the flag left set; after a new vault it was the new vault's meta, so the old run listed the new vault. The run now reads its meta once and hands it to `refold`, `push` and `pull`, and checks the generation between the caught 429 and the pull. Engine test: a push held and then answered 429 while the grower stops, and again while the grower starts a second vault; the stale run ends with the stop error, sets no busy text, lists nothing, and the new vault's own listing count does not change. Fails against the old engine.
3. **The vault ceilings could be spent by one IPv6 host, the total for good, and a KV write could refuse a valid creation** (R1-3). Every counter keyed on the full address; an IPv6 host rotating within its /64 was a fresh address each time. `addressKey` now keys an IPv6 address by its /64 (an IPv4 address as it is; an IPv4-mapped one by its IPv4 part), for the creation counters, the byte allowance and the rate limit alike; `/about/how` and `/about/formats` say so. The total and the day's ceiling now refuse with different sentences ("Sync is not taking new vaults for now… joining an existing vault still works" and "…try again tomorrow"), since "try again another day" was false once the total was the reason. The counters are written after the decision, and a write that fails (KV takes one write a second per key) is a warning and a count short by one, not a refusal. `creationCeilings` takes a JSON number as well as a digit string. `keep_vars: true` goes in `wrangler.jsonc` so a ceiling raised in the dashboard survives the next deploy; `docs/DEPLOY.md` says where. Server tests: eight rotations within one /64 get five vaults; a failing write still says ok; a number ceiling counts; the day and total ceilings answer their own kinds. Engine test: the two sentences.

## The formats page and the public claims

4. **`/about/formats` had drifted in seven places** (R1-4). Each checked against the code and corrected: the address limits (5 per address, the shared ceilings and their 503s); photographs sealed before ids were bound carry `vaultId|photo` alone, and a reader tries the named form first as the app does; the key is cleaned by dropping every character outside A–Z and 0–9 and the pairing-link prefix, not dashes alone; the fingerprint is over exactly `JSON.stringify(changes)`, compact and in the changes' own key order, and the hour is padded to 13 digits; the last part of `t` is the writer, the 12-character device id plus a 4-character tab tag (or `zz…` for the number repair), matched to the manifest's `device` by its first 12 characters; record ids carry a kind prefix, the minting stamp in base 36 and the writer, with the first builds' short ids still valid; and a sealed photograph is the full JPEG plus the 320-pixel thumbnail plus 17 bytes and the 16-byte tag, not "a few bytes larger than its JPEG".
5. **The formats test could not see the page drift** (R1-5). It now reads `+page.svelte`, strips the markup and parses every constant the decoder needs out of the sentences (the salt, the three infos, the id prefix, alphabet and length, the version byte and IV length, both associated-data shapes and the old photo form, the hour padding, the fingerprint digits, the four limits, the id prefixes, the writer's two lengths), then decodes with those values and nothing from `crypto.ts`: a batch, a photograph under the named binding, an older one under the plain binding, the batch fingerprint. A sentence that changes on either side fails the test by name (checked by editing the page's limit: it fails).
6. **The provenance line and the first-load figure were wrong, and the footer overstated** (R1-6). The README and the Show HN draft now say how the rounds were made: rounds four and five passes over a checkout, round six the author's own, outside models against the live site from round seven, with the two briefs named; "4 through 18" is "4 onward". The first-load figure now says what the page itself loads (about 100 kB of script and style compressed plus 160 kB of fonts) and what the worker then installs for offline use (about 260 kB of script and style in all); `scripts/dev/first-load.mjs` prints both. The settings footer and the site footer say "beyond short-lived rate counters", and `/about/how` has one sentence on what those are, how they are keyed and that they expire within two days.

## What a page says

7. **The clock-time frost line contradicted its own date, and did not say whose clock** (R1-7). Solar 23:00 Wednesday the 14th at Mendoza is 01:00 Thursday on the clock, and the line said "01:00 Thursday (2026-10-14…)". The bracketed date is now the clock day of the same instant, and the line says ", your time", since the reader's clock is the only clock the device knows: it is the site's when they are there and near it when they are not, and the line never claims to be the site's own. Unit test: the 23:00 → 01:00 case with both dates.
8. **The archetype sentence in the species head read as methodology** (R1-8). "Grouped with the Cactus or succulent in the archetype table, by the genus Astrophytum, which is reliably one kind of plant" is now "Cactus or succulent (by genus)", with the long form as the line's title; the cultivation cards say where the table is used.
