# Round 60 review: accessibility and performance (area "a11y-perf")

The round fixed most of what round 59 found (the footer shift on the lists, the tab bar flip, the forced-colours chips, tap targets, the Water focus on the plants list, the blank first paint), but the new round-sixty UI brings back the same class of bugs in new places. The worst is a keyboard trap: a toast whose action was raised while focus was on the page holds Tab forever (P1, WCAG 2.1.2, level A). Select mode, import, the "···" menu and the Wanted form all drop focus to `<body>`. The layout imports the whole grow barrel, so every page, public ones included, ships about 30 KB gzip of grower code it never draws. The sample collection's bar and Today shift their pages by 0.17 to 0.54.

How I tested. Everything ran against the shared build at 127.0.0.1:4173 (commit 21257b7, four-species fixture), with Chromium 1194 through Playwright and axe-core 4.11, on Node 22. Scripts are in /tmp/r60rev/a11y/; screenshots are in /tmp/r60rev/out/shots/a11y/. Private pages were measured with a collection written straight into IndexedDB (`inject` in lib.mjs, generated by gen.mjs):
- 3 places, a seed batch, a shared number (two plants on 2026-0042), a followed species (the Wanted list), and 12, 300 or 3,000 plants;
- one plant with 200 events and 50 photographs whose pixels were made in the page.

What ran:
- axe: 242 runs in four groups:
  - 16 public states;
  - 11 empty private pages;
  - 31 seeded states (menu open, select mode, move, archive confirm, toast, Wanted form, chooser, three import stages, calendar open, backup preview, and others);
  - 6 sample-collection states.

  Each in light and dark, at 390 and 1280. Then 16 more runs with every `<details>` open.
- A keyboard walk of every round-sixty control at 1280, logging focus after each key and every live-region mutation.
- 320 px at 200% browser text (a profile preference, as the e2e suite does) and 320 × 256 CSS px (1280 × 1024 at 400%) on 65 states.
- Forced colours.
- Reduced motion.
- Throttled loads (CPU 4×, slow 4G at 150 ms and 1.6 Mbps, cold HTTP cache, no service worker), 2 or 3 runs each.
- CLS attribution with fonts blocked and loaded.
- Bytes per route from the client manifest.
- A memory loop.

Limits:
- The machine ran at load 11 to 48 on 2 CPUs with about 1.5 GB free. Timings are noisy, and I compare them within a run rather than with round 59's absolute figures.
- Three renderer crashes ("Target crashed") happened under that memory pressure and did not recur on rerun. I do not attribute them to the app.
- No real screen reader: semantics come from aria snapshots and DOM measurement.
- No round-59 build to run side by side, so a regression is named one only where the code or the bytes show the cause.

Tests: `/tmp/r60rev/out/tests/a11y-perf--round60.spec.ts` (7 e2e tests, all FAIL on current code; run against 4173 with `PW_CHROMIUM=/opt/pw-browsers/chromium`, all 7 failed as stated) and `/tmp/r60rev/out/tests/a11y-perf--layout-bundle.test.ts` (unit, FAILS; its logic checked by hand against the source and manifest).

## Findings

### 1. P1. A toast with an action traps Tab for good when it was raised with focus on the page (confirmed)

- `src/lib/ui/ToastBar.svelte:50-54` (`onKey`) and `:18-21` (`back`). On Tab from the toast's last button, `onKey` calls `preventDefault()` and then `back()`. When `toast.origin` is null (the toast was raised while `document.activeElement` was `<body>`), `back()` does nothing and "Back to where you were" is not rendered. So Undo is the last button and Tab is swallowed on it. Focus inside the toast also holds its timer (`hold()` on focusin), so the toast never leaves.
- Measured on `/plants`, fresh browser, 3 plants (trap.mjs): the persistence toast ("This browser has not promised to keep your data… Back up") is raised at load.
  - The Tab sequence: Skip to content, Menu, Species, … Add a plant, then Back up, Back up, Back up and Back up (14 presses).
  - 25 s later the toast was still there and focus still on "Back up".
  - Shift+Tab and Escape get out; Tab never does. Screenshot `trap-toast.png`.
- The same happens after every select-mode action (finding 2 leaves focus on `<body>`, so `origin` is null). kb2.mjs: Tab to Undo, then Tab, Tab, then 9 s later still on Undo.
- Real-world trigger: `navigator.storage.persist()` resolves false on most first visits in Chrome. GrowLayer raises that toast with an action on the first page load that has a plant.
- Should: Tab past the toast's last control always leaves it.
- Smallest fix: in `onKey`, only `preventDefault()` when `toast.origin?.isConnected`, and otherwise let the Tab through and `toast.release()`. Better still: when `origin` is null, record the element the user Tabbed from into the toast (the `relatedTarget` of the toast's first focusin) and use that as the way back.
- Test: `a11y-perf 1` (FAILS).

### 2. P2. Round sixty's new actions drop keyboard focus to `<body>` (confirmed)

This is round 59's finding 1 again, in the new code. Measured with kb.mjs at 1280 (log `kb-1280.log`).

- **Select mode** (`src/lib/ui/grow/SelectMode.svelte`). Every control is `disabled={busy …}` or is replaced by the next panel.
  - After Enter on each of these, `document.activeElement` is BODY: Water (`#sel-water`, line 104), "Move to a place" (the panel replaces the button; focus is not moved to the picker), "Move N" (line 98; the panel is then removed), Archive, and "Yes, archive".
  - So the toast's `origin` is null: Tab does not divert to Undo, and Undo then traps (finding 1). Tab from `<body>` landed on "Move to a place"; the Undo was unreached.
- **Import** (`src/routes/plants/import/+page.svelte:209, 283`).
  - Enter on "Check names" leaves focus on BODY, because the button is disabled while `checking`. The review is scrolled into view (line 115) but not focused.
  - Enter on "Add N plants" leaves focus on BODY, because the button is disabled while adding and the review is then removed. The next Tab went to the footer's "How it is made", below the result.
  - `#imp-done` is `role="status"` but is inserted with its text (`{#if result}`), the pattern round 59 fixed for the toast. The MutationObserver logged it as INSERTED-WITH-TEXT.
- **"···" menu, Download as a spreadsheet** (`PlantsMenu.svelte:21-27`): `close()` removes the focused item and `busy` disables the "···" button, so focus goes to BODY.
- **Wanted note** (`PlantsFoot.svelte:24-29`): Save and Cancel remove the form (`editing = null`), so focus goes to BODY.
- **Today, "Water N here"** (`src/routes/today/+page.svelte:184-199`): the button is replaced by "Watered just now · Undo" and focus goes to BODY. Round 59's finding 1 named this; the round fixed the Undo direction (line 210) but not this one. Still open from 59.
- Should: focus stays on, or moves to, a named control: the Water button (aria-disabled, as the list's), the picker when Move opens, the result when import finishes, the "···" button after Download, "Add a note" after Save.
- Smallest fixes:
  - Select mode: use `aria-disabled` plus the existing `busy` guard instead of `disabled`, and `tick().then(() => document.getElementById('sel-loc')?.focus())` when Move opens. After Move and Archive, focus `#sel-move` or `#select-toggle`.
  - Import: `aria-disabled` on `#imp-check` and `#imp-add`; mount `#imp-done`'s status element always, and focus the done block's heading (`tabindex=-1`) after the add.
  - PlantsMenu: `close(true)` in `sheet()`, and no `disabled={busy}` on the trigger.
  - PlantsFoot: refocus the row's Edit button after save or cancel.
  - Today: after `waterHere`, focus the stop's done-row Undo or the stop heading (`h3[tabindex=-1]` already exists, line 266).
- Test: `a11y-perf 2` (FAILS).

### 3. P2. Every page ships the grow layer: about 30 KB gzip of JS and 8 KB of CSS no public page draws (confirmed)

- `src/routes/+layout.svelte:23` imports `GrowLayer` from the barrel `$lib/ui/grow` (index.ts). A Svelte component module is not tree-shaken out of a barrel, so the layout chunk imports the whole barrel: chunk `grow` (QUAt4UqM.js). PlantsMenu's `downloadPlantsSheet` brings the `backup` module with it (DwuPNoWd.js).
- From `.svelte-kit/output/client/.vite/manifest.json` (bytes.cjs): the chunks reachable from the shell only through `grow` are 71.2 KB raw and 29.6 KB gzip: grow 33.6/13.2, backup 28.4/11.9, LocationPicker, SpeciesName, photo-label, index.svelte, demo, links. The `grow` CSS (8.3 KB raw) is inlined into every page's HTML: `selrows` and `demobar` appear in the HTML of `/` and of every species page.
- The network capture of a cold visitor load of `/` and `/species/copiapoa-cinerea` lists QUAt4UqM.js (13 KB) and DwuPNoWd.js (12 KB) among the scripts fetched.
- JS transferred per route (gzip, cold, perf.mjs) against round 59's table:

  | Route | Round 59 (KB) | Round 60 (KB) |
  |---|---|---|
  | `/` | 129 | 181 |
  | species page | 143 | 185 |
  | `/plants` | 104 | 147 |
  | plant page | 138 | 179 |

  The grow and backup chunks account for about 25 KB of each increase. The rest on `/` is the feature block (the cultivation sheet chunk, 9 KB, Glance and the Climograph).
- Should: a visitor's page carries only the sample banner's few lines.
- Smallest fix: `import GrowLayer from '$lib/ui/grow/GrowLayer.svelte'`. GrowLayer's own graph is vault, demo, toast and DemoBar, and none of them reaches backup. Do the same for the four route imports (`plants/+page.svelte:26`, `plants/[acc]:40`, `today:22`, `labels:34`), so `/labels` stops loading SelectMode and the Wanted list. Optionally `import()` `demo-seed` only when `inDemo()`.
- Test: `a11y-perf--layout-bundle.test.ts` (FAILS).

### 6. P2. Forced colours: the current tab is unreadable, and the toast has no edge (confirmed)

- The round-sixty rule (`theme.css:436-439`) sets `a[aria-current='page'] { background: Highlight; color: HighlightText }`. But `#tabbar a.on { color: var(--accent) }` (`+layout.svelte:406`) has an id in its selector and wins.
- Measured (fc2.mjs) on the current tab:
  - light: rgb(18,121,90) on Highlight rgba(5,0,73), about 1.5:1;
  - dark: rgb(95,184,148) on rgba(0,230,255), about 1.6:1.
- Screenshots `fc-today-cal.png` and `fc-plants-select-toast.png`: "Today" and "My plants" fade into the highlight. The desktop top nav's `a.on` is probably affected the same way; I measured only the tab bar.
- The toast: `.toast` and `.undo` have `border: 0`, so in forced colours the toast is text on Canvas over the page, and Undo looks like a word. Screenshot `fc-plants-select-toast.png`: the toast sits over the select bar's "Print labels" with nothing to tell them apart.
- Smallest fix:
  - Add `!important` to the forced-colours `color: HighlightText`, or add `#tabbar a.on, .topnav a.on` to that selector list.
  - Add `@media (forced-colors: active) { .toast, .toast .undo { border: 1px solid CanvasText } }`.
- Test: `a11y-perf 6` (FAILS).

### 11. P3. Live regions and names in the new UI (confirmed)

- Calendar: `{#if msg}<p role="status">` (`CalendarExport.svelte:41`) is created with its text, which many screen readers do not announce. Keep the `<p role=status>` mounted.
- Toast: `aria-atomic` on the region makes each announcement end in "Undo Back to where you were". Put the buttons outside the atomic region, or give the text its own `role=status` span.
- Select mode: the toggle both relabels ("Select" / "Done selecting") and sets `aria-pressed`, so it is announced as "Done selecting, toggle button, pressed". Keep one or the other.
- Select mode: `.selbar` has `role="toolbar"` without the toolbar's arrow-key model; every button is a Tab stop. Drop the role, or use `role="group"`.
- Import review: the "Use it" buttons are all named "Use it". Name them "Use Copiapoa cinerea on line 2".
- Import mapping: the comboboxes' names include the example values ("Name (needed) Copiapoa cinerea", "Place GH", "Number 1"), because `.eg` sits inside the `<label>`. Move it to `aria-describedby`.
- Wanted: "Add a note" opens a form but has no `aria-expanded`.
- "···" menu: no Home or End. `aria-controls="plants-menu"` points at nothing while the menu is closed (axe "needs review"). The disabled "Download" item (empty collection) cannot take focus, so ArrowDown does nothing visible. Per the APG, use `aria-disabled` on menu items.
- Species page section links (`nav.tabs`, `+page.svelte:125-133`): `goTab` prevents the default and scrolls, so focus stays in the nav. The next Tab went to "Habitat", not into the Climate section. Focus the section heading (`tabindex=-1`) after the scroll. The active link has `class:on` but no `aria-current`.

## Checked and sound

- **axe.** Across 242 runs, the only violations are the ones above (label-in-name, the import contrast, the demo h1, two link-in-text-blocks). Five runs errored on my own harness (opening species cards by locator; one refused-page timeout). The chooser, import (paste, CSV mapping, review, done), backup preview, both locked demo pages apart from the h1, the menu and select states, calendar open, and both 404s are otherwise clean in both themes and widths.
- **Tab bar flip.** Fixed. With the app's scripts blocked, a server-rendered species page draws the grower's five tabs before paint (`data-grower=1`), for a grower with plants, one with only a seed batch, and one with only a dead plant. The front page and the layout do not fight over `cultifolio.hasMine` (flip.mjs).
- **Footer hold.** CLS on warm loads with 300 plants at 4× CPU:
