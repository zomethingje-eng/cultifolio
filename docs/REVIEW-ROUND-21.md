# Review round twenty-one: two reviews of `f9e84b0`, triaged

The second reviewer's twelfth pass (two findings) and the first reviewer's round twenty (fourteen findings, three readers). Every finding was checked in the source; all sixteen are real and all are done. The two reviewers disagreed about the most important one, and both were right about their own: the vault ceilings did not hold against a burst, and the local preview could not create a vault at all. "R1-n" is the second reviewer's numbering this time (the shorter review), "R2-n" the first reviewer's.

## The vault ceilings

1. **A burst of creations was not limited, and the counters missed most of it** (R2-1; the reviewer's one thing to fix). Round twenty made a failed KV write non-fatal, and that failing write was the only thing that had stopped a burst: KV takes one write a second per key and caches reads for a minute per location, so twenty creations in one second all read zero, all wrote one, and all were allowed. The counters now live in one Durable Object (`src/lib/server/counters.ts`, class `Counters`, bound as `COUNTERS`): the read, the decision and the write are one step inside one object, which takes one request at a time, so a burst is counted exactly. The SvelteKit adapter's worker exports only the app, so `scripts/attach-do.mjs` appends the class's export after every build (it is the last step of `npm run build`), and `wrangler.jsonc` binds it with a `new_sqlite_classes` migration. Without the binding the KV path stands, and there the address's own count is written first and a write that fails refuses the creation, since that write is what stops a burst from one address; the shared counters stay best-effort. Server test: a stand-in with the object's contract (one request at a time; read, decide, write inside it) under a burst of a hundred from one /64 allows five and counts five, and three hundred addresses against a day's fifty allow exactly fifty. Against `wrangler dev` with the object bound: twenty creations fired at once from one address, three allowed (two had been made earlier that day) and seventeen refused.
2. **The documented local preview could not create a vault, and the smoke suite was red** (R1-1; the reviewer's one thing to fix). The vault route passed `getClientAddress()` straight to `allowCreation`, and round twenty's `addressKey` called `.includes` on it; a local runtime that gives no address made every creation a 500 and both sync journeys fail. The route now goes through `clientIp`, as every other counter does, which turns a missing address into `unknown`. Engine test: the route with `getClientAddress` answering null creates the vault and counts it under `unknown`.
3. **The e2e suite failed on the third run of a day** (R2-2). `wrangler dev` keeps its counters in `.wrangler/state` between runs, and every run creates vaults from one address. The e2e web server now clears that state before it starts (`scripts/dev/fresh-state.mjs`).
4. **A KV read that failed was reported as the permanent ceiling** (R2-6). It is now `unavailable`: "Sync could not count new vaults just now… try again in a minute", 503 with `retry-after: 60`. The object not answering is the same.
5. **`keep_vars` made "remove `SYNC_OPEN` to close sync" wrong** (R2-3). A deployed variable the file no longer names survives with `keep_vars`, and a dashboard value is replaced by the file's on the next deploy. The README and `docs/DEPLOY.md` now say the one true thing: the file decides `SYNC_OPEN`; set it to `"0"` there to close creation, never delete it.

## Sync

6. **A stopped run still ran the number repair and stamped a sync time** (R2-4). The set-aside retry's catch rethrew only a 429, so the stop error from `takeBatch`'s key check was logged as a failed re-read and the loop went on into `repairNumbers()`; and `this.lastSync` was set before `save(m)` made the staleness check. The catch now rethrows when the run is stale, and the sync time is shown only after the save has passed. Engine test: a run stopped during its pull shows no sync time and makes no further request; a run stopped during a set-aside re-read does not call the repair (fails against the old engine).

## The live check

7. **The forecast leg could not see MET, and the names leg was often all hits** (R2-5). The Worker caches a cell for an hour, so `lc=` busted only the outer edge. The check now asks a cell London's longitude minus a hundredth of a degree per minute of the day, thirty cells in rotation, so MET is really asked once per run; the names leg asks its genus by a prefix of four to seven letters, ninety keys in rotation instead of thirty. The forecast route's own cache key moves to the private host the names route uses (`https://cache.cultifolio/…`): the reviewer's reading of round nineteen's failure was right, the old key was byte-for-byte a real URL of the site, and the raw object stored under it was what the edge handed back.

## The formats page and the claims

8. **Record ids and the example change** (R2-7). The page now says the time is exactly 8 base-36 digits (which is how the app reads it), the counter two or more digits, that ids from before round eight carry a 12-character writer, that `photosMissing` is absent when empty, and names the photo path's two ids apart; the example change carries an app-shaped 16-character writer and an id minted at its own stamp.
9. **The formats test now parses the rest** (R2-8): first or last bytes and the modulus of the id rule, the excluded letters against the code's alphabet, "not a decoding", which photo form to try first, the length's endianness (and reads a real length that way), the tag length, first or last change in the batch name and its device length, the 12/4 writer split, the five-minute hold, the hex counter, base 36, the 409, the 507 and its 2 GB, the 32 buckets, and the example change against `hlcEncode`. Each of the nine mutations the reviewer made to the page was made again here, and each fails the test.

11. **The provenance line and the install figure** (R2-10). README and the draft say round nineteen asked what to improve; the install figure adds the maps and icons the worker also installs (about 160 kB).

## UI

The caption is the theme's hint ink with no opacity on a slightly lighter tint (4.7:1 at the worst hue in light mode, computed over every hue; the a11y e2e now measures it on an owned tile in both schemes and checks the caption is read out); the initial scales with the box (`cqh`); only the initial is `aria-hidden`; and the tint comes from the genus, not the family, so a bench of Cactaceae is not one beige.
