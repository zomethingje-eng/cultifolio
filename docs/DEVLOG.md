# Development log

Milestone-by-milestone notes on how Cultifolio was built and why. The public README is at the repo root; this file is the history.

Cultifolio v3 is a rebuild of an earlier app ("Herbarium v2"), which stays deployed on its own Worker until this one replaces it at cultifolio.com.

## Milestone 1 — walking skeleton (this build)

What works:

- **Species dossiers.** One JSON per taxon (`s/v1/<gbifKey>.json`), built once by `src/lib/dossier/build.ts` from GBIF (backbone, WCVP distributions, occurrences), iNaturalist (photos, `photo_license=cc0,cc-by,cc-by-sa` only), Wikidata (cross-IDs, CC0), Wikipedia (lead paragraph, CC BY-SA, kept segregated), Wikimedia Commons (per-file licence), OpenAlex (CC0). Every upstream's answer is recorded as `ok / none / refused / error`; only `none` is ever rendered as an absence. Occurrence records are filtered to CC0/CC-BY before anything is derived from them, and the page says how far the restricted records would have moved the habitat centre.
- **Server-rendered species pages** at `/species/<slug>` with meta tags and JSON-LD, readable with JavaScript off.
- **Front page** in the Bench look: featured species plus a grid grouped by native region.
- **Collection core**: accessions, timeline events (with measurements, treatments, death causes), per-plant notes and per-species notes, in an append-only IndexedDB change log with hybrid logical clocks and field-level last-writer-wins merge. Numbers are never reused. The numbering scheme is a vault setting (year-prefixed by default, organisation prefix later).
- **v2 importer** (`/plants/import`): takes a v2 backup JSON, keeps your numbers, writes nothing back.
- **Export**: the whole change log as JSON.
- **Still maps** from Natural Earth coastlines, referenced as one cached static SVG.
- **Self-hosted fonts** (OFL, via @fontsource).

## Milestone 2 — data tier

- **Habitat climate** from a packed 0.05° grid: CHELSA V2.1 1981–2010 monthly normals (tasmax, tasmin, tas, pr, rsds→DLI, hurs, vpd, sfcWind; CC0) plus ETOPO 2022 elevation, 97 int16 layers interleaved per cell so a lookup is one 194-byte range read (`src/lib/climate/`). Extremes (absolute and 1st-percentile minimum, 99th-percentile maximum, frost nights per year) from NASA POWER's daily MERRA-2 series 1981–2024, lapse-corrected from POWER's cell elevation to the grid cell's at 6.5 °C/km, cached forever per POWER cell.
- **Frost watch** at `/frost` and `/api/forecast`: MET Norway Locationforecast (CC BY 4.0, worldwide) reduced to daily min/max, NWS frost/freeze alerts for US points, edge-cached an hour per 0.01° cell.
- Corpus script flags: `--grid climate` (use the packed grid), `--force` (rebuild species whose dossier is already clean; by default those are kept, so a killed run restarts with the same command, and the index is regenerated from every dossier on disk).

## Milestone 3a — benches

- **Location tree** (`location` records, any depth: room › bench › shelf › tray). Conditions (indoor, floor °C, PPFD, light hours, coordinates, altitude) are inherited: a shelf with nothing set reports its nearest ancestor's values and says which ancestor they came from. `/benches` lists the tree with plant counts; `/benches/[id]` edits one place.
- **Whole-bench actions**: water all / feed all record one event per plant in a single commit; **audit mode** ticks off what is physically present and stamps `audit` events, so each plant carries a "last seen" date and the bench page flags plants not seen recently.
- **Frost watch per place** for outdoor locations with coordinates; the floor temperature of a protected place is added to the forecast before the risk level is computed.
- v2 benches import as locations (`l-v2-…` ids); plants whose v2 bench text matches no bench keep the free text and can be converted to a location from `/benches` in one click.
- `id`, `kind` and `_t` are reserved record fields; the log refuses a change that sets them.

## Milestone 3b — sowings and propagation

- A **sowing** is any propagation batch (`sowing` records, numbered `S2026-001` per year): seed, cuttings, offsets, leaf cuttings, divisions, bulbils, grafts. It records what was started, from where (seed source and lot, or the parent plant for vegetative material), medium, container, pre-treatment, bottom heat, cover, and where it sits.
- Its timeline takes **germination counts** (cumulative: "up so far"), **losses** with a cause, notes, and **pot up**, which mints one accession per plant potted in a single commit: the batch as `sowingId`, provenance derived from the seed's (wild seed → F1 plants; vegetative → veg), the parent's field number and cultivar carried, an acquire event each, and a potup event on the batch naming them. `/sowings` lists batches with day count, germination rate and potted count; `/sowings/[id]` is the batch page; `/plants/[acc]` links back and offers **Propagate** (a vegetative batch from that plant, recorded on its timeline).
- Fixed: event ids were derived from the last 14 characters of the HLC, which on a real device collided on nearly every write (a later event silently replaced an earlier one). Ids are now wall time + counter in base 36 plus a device tag, with a regression test.

## Milestone 3c — the user's path, and photographs

- **Flow.** Species → "Add one to my plants" / "Sow seed" arrive prefilled (species, GBIF key, last-used place or the bench you came from). The species page shows what you grow of it and holds your own notes. The plant page has **Move** (inline new place), **Habitat versus here** (the species' DLI range and cold floor against the bench's figures; a missing figure hands off to the bench's edit form with `?edit=1`), and an **Its year** tile that says whether the plant should be growing or resting this month in your hemisphere. Bench pages offer "Add a plant here" and "Sow here".
- **Photographs** of your own plants and sowings. Camera or file; resized on the device (long edge 1600 px, 320 px thumbnail, JPEG q0.85) so the original never leaves the phone and is not kept; the date comes from EXIF `DateTimeOriginal` when present (`src/lib/photo/exif.ts` reads that tag and orientation and nothing else — no GPS, no camera model), else the day it was added. Metadata is a `photo` record in the change log (so it syncs and sits on the timeline); the pixels live in the vault's `photos` store under the same id, with a SHA-256 so sync can tell a blob is already there. A plant's **cover** is its chosen photo, else its newest; it is the hero on the plant page and the thumbnail in lists. The lightbox captions, redates, sets the cover and removes; arrow keys and swipes move through the set. The species page shows *Your photographs* ahead of the open ones.

## Milestone 3d — backup

- `/backup` (the old `/plants/import` redirects there). **Take a backup** downloads one zip, `cultifolio-YYYY-MM-DD.cultifolio.zip`: `manifest.json` (format, version, device, counts, numbering scheme), `changes.json` (the whole change log), `photos/<id>.jpg` and `photos/<id>.t.jpg` (stored, not deflated), and `plants.csv` (one row per plant with the location path resolved, BOM for Excel; for people, not for import). The last backup time is kept in vault meta and shown on the page.
- **Restore** reads a backup zip, the older changes-only JSON, or a v2 Herbarium backup (detected when the zip/JSON parse fails and the file is JSON with accessions), and shows what is in it and what merging would do before anything changes. **Merge** appends only changes this device has not seen (by HLC) and photos it lacks, so restoring an old file over a newer collection loses nothing and restoring twice changes nothing. **Replace** wipes the device first and reloads. `src/lib/backup/backup.ts` is pure (build/read/preview/CSV, unit-tested with a round trip); `io.ts` wires the vault.

## Milestone 3e — cultivars and hybrids

- A plant is one of three things, recorded as `nameKind` on the accession (and sowing): a **species** (`taxonName` a binomial), a **cultivar** of a known species (binomial + `cultivar`), or a **hybrid** (`taxonName` is the genus or nothogenus; `parentage` holds the cross when known). Named `nameKind` because `kind` is the log's record type. Old records read as species, or cultivar when a cultivar is set (`kindOf()`).
- `parseName()` reads what a label says: "Haworthia truncata 'Lime Green'" → cultivar; "Echeveria 'Blue Curls'" → hybrid of unstated parentage under *Echeveria*; "Ariocarpus retusus x A. trigonus" → hybrid under *Ariocarpus* with parentage "Ariocarpus retusus × Ariocarpus trigonus" (abbreviated genera expanded); "Echeveria × imbricata" → a nothospecies the backbone may know; "× Graptoveria 'Fred Ives'" → nothogenus. The picker matches a genus-only name at genus rank in GBIF and offers no species suggestions for it.
- The plant page shows a hybrid/cultivar pill, the parents linked to their species pages where the corpus has them, "A hybrid: no habitat of its own" in place of the climate tiles (no Habitat-versus-here, no species-page button), and a parentage row. Lists show the pill. The species page's "you grow N" counts cultivars of the species, not hybrids of it. Hybrids never enter the corpus; there is no cultivar registry and the app does not pretend to one.

## Corpus at scale: the bulk path and the derived list

Per-species API calls are the wrong shape past a few hundred species. Two downloads replace the two slowest legs; `buildDossier()` is unchanged, because `bulkFetcher()` (`src/lib/dossier/bulk.ts`) answers the distribution and occurrence URLs from the files and passes everything else through, so a dossier built either way is the same dossier.

```
npm run bulk -- wcvp                       # Kew's WCVP checklist → bulk/wcvp_names.csv, bulk/wcvp_distribution.csv (~1 GB unpacked)
set GBIF_USER=… GBIF_PASSWORD=… GBIF_EMAIL=…   (a free gbif.org account; PowerShell: $env:GBIF_USER="…")
npm run bulk -- gbif names.txt --wait      # matches every name, counts records per species, requests ONE occurrence download for those under --max-records, waits → bulk/occurrence.zip (read in place)
npm run dossier -- names.txt --grid climate --bulk bulk   # the build, reading from bulk/; photos, Wikipedia and literature still per species
```

- WCVP is streamed in two passes (every genus in the list is kept, so a synonym resolving within the genus still finds its range); occurrences are sampled per species as the file streams (≤4,000 each, chosen by a stable hash of the record id, so a rebuild finds the same habitat centre). `bulk/keys.json` caches name → key; `bulk/unresolved.txt` lists what the backbone could not place.
- A species the files lack falls through to the API, so a fresh name still builds. The build prints how many requests each path served.

**Deriving the names list** (`npm run derive -- --inat 2500 --out names-big.txt`): iNaturalist "captive/cultivated" observation counts under Plantae (the head of what people grow, across every kind of grower), resolved against WCVP (synonyms and infraspecific names to their accepted species; the GBIF backbone only for names Kew lacks), minus the families in `scripts/excluded-families.txt` (cereals, turf, timber), plus every accepted species of the `scripts/specialist-genera.txt` genera as WCVP lists them, so `npm run bulk -- wcvp` comes first (the collector genera, taken whole because a Namaqualand bulb never out-observes a pothos). The genera come whole (about 6,200 accepted species in WCVP); `--inat` sets how many of the most-cultivated iNaturalist species are taken on top, so the list is roughly 6,200 plus that number. `names-big.txt.csv` says why each name is there, with its family and count, for pruning. Two things learned on the first real run: captive observations on iNaturalist are always casual grade, so a `quality_grade` filter returns nothing; and the GBIF backbone is the wrong source for genus membership, since it lists unresolved names as accepted (122 Aeonium against WCVP's 40) and its match fails on homonyms (Mammillaria). Everything is cached under `bulk/derive/` so a rerun with a different `--inat` is instant.

## Milestone 3f — the note in short, and labels

- **In short** (`src/lib/core/note.ts`, `generatedNote()`): the cultivation sheet condensed to one paragraph by rule, one sentence per card, in the sheet's own figures, with the months shifted to the reader's hemisphere (from the first bench with coordinates; north otherwise, and the card says so). The card lists which rows each sentence came from. Nothing is written by a model; the dossier's `note` field stays reserved for that if it ever happens and is shown in preference when present.
- **Labels** (`/labels`, from the plants list, a plant's ID card, or a bench's quickbar with `?acc=` / `?loc=`): pick plants, pick a sheet (Avery 5160, 5163, 5167 pot-rim, L7160 A4, or strips to cut), skip the cells already used on a part sheet, and print. The preview is at true size in mm and `@page` follows the sheet, so the printer gets the sheet. Each label: number, field number, name (cultivar, parentage for a hybrid), optional source and date, an optional **care line** from the sheet (`careLine()`: "winter grower Nov–Feb · >4 °C · full sun · dry between"), and a QR code (the `qrcode` package, SVG) that opens the plant's page on this site. Choices are remembered per browser.

## Milestone 4 — sync (end-to-end encrypted)

- **One vault key**, made on the first device (`newVaultKey()`: 30 symbols from an unambiguous alphabet, six groups of five, ~147 bits, drawn without bias). HKDF splits it into an AES-256-GCM key (never leaves the device, non-extractable) and an auth token; the vault id is a hash of the token. The server stores a hash of the token and ciphertext, and can neither read a byte nor recover a lost key. `src/lib/sync/crypto.ts`, WebCrypto only, unit-tested (round trip, wrong key, wrong purpose, tampering, photo packing).
- **Server** (`src/lib/server/sync.ts`, `/api/sync/*`): zero-knowledge storage on R2 under `vault/<id>/` — `meta.json`, `log/<hlc>.bin` (one sealed batch per push, named by its last change's HLC so a list is a pull), `photo/<id>.bin`. Nothing is rewritten or deleted. Joining requires an existing vault (`create: false`), so a mistyped key cannot quietly become a fresh empty vault. `SYNC_OPEN=1` lets any vault sync (dev and pre-launch); the licence check lands on `entitlement`.
- **Engine** (`src/lib/sync/engine.svelte.ts`): first push sends the whole log; after that only changes stamped by this device's clock. Pull lists batches after a cursor, skips its own, ingests through the same merge as backups (per field, latest HLC wins). Photos by id, immutable, both ways. Runs on app load, 2.5 s after any local write, and when the browser comes back online; the topbar shows a ⟳ that spins while it works and turns red on an error.
- **Page** (`/sync`): set up (key shown once with a QR, must tick "I have saved it"), join (type, paste, or scan the QR with the camera where `BarcodeDetector` exists), status tiles, "Add another device", stop syncing here (nothing deleted). The e2e test runs two isolated browsers through create → join → edits both ways → a concurrent edit of one field resolving the same way on both → a wrong key refused.

### Building the climate grid (once, on your PC)

```
pip install rasterio numpy requests
python scripts/pack-climate.py
```

Downloads 96 CHELSA GeoTIFFs (~20 GB, deleted as they are packed) and one ETOPO file, resamples each to 0.05° by mean, writes `climate/climate.grid` (5.0 GB) and `climate/climate.json`. Resumable; a crash costs one layer. Probe a cell afterwards:

```
python scripts/pack-climate.py --probe -24.877 -70.504
```

Then rebuild the corpus with climate:

```
npx tsx --tsconfig tsconfig.scripts.json scripts/build-dossiers.ts names.txt --grid climate
```

Upload the grid to R2 when the bucket exists (the Worker reads it with ranged GETs):

```
npx wrangler r2 object put cultifolio/climate/v1/climate.grid --file=climate/climate.grid
npx wrangler r2 object put cultifolio/climate/v1/climate.json --file=climate/climate.json --content-type=application/json
```

## Rules carried over from v2

- A refusal is not an absence. A source that did not answer is never rendered as "none".
- Unknown is not open. A record whose licence nobody stated is not usable.
- Every derived number says where it came from.
- Anything whose shape can change carries a version in its path (`s/v1/`), and the schema refuses to serve what does not parse.
- Accession numbers are never reused; dead plants keep theirs.
- A field number is not a provenance.

## Licences

Client: MIT. Worker/server code: AGPL-3.0 (to be split when sync lands). Data: see the footer on every page and each photograph's credit.

**Dataset bundle** (`npm run export -- --dir static --version 2026.09 --out cultifolio-corpus-2026.09.zip`): everything the build wrote, packaged for people who are not running the app. `species/<slug>.json` verbatim; `species.csv` one row per species with the habitat centre, growing season, cold figures and counts, empty where the build could not derive; `climate.csv` twelve rows per species; `index.json`; `build-report.txt`; a README saying how it was derived and a LICENSE.md that gives the derived figures CC BY 4.0 and lists which fields keep their source licence (Wikipedia summaries are CC BY-SA; occurrence rows carry their own code; photos are links and credits only). `scripts/export-corpus-lib.ts` is the pure builder, `tests/unit/export.test.ts` runs it on the fixtures.

**First contact with a 9,000-species GBIF download.** Requested naively it came to 122 million records: a few hundred street trees and garden weeds in the iNaturalist head (red maple, ginkgo, olive) carry millions each, and the build samples a couple of thousand per species anyway. So `npm run bulk -- gbif` now counts records per species first (`bulk/counts.json`, cached) and leaves any species over `--max-records` (default 100,000; the list goes to `bulk/api-path.txt`) to the per-species API, which serves a few hundred records and is all the habitat centre needs; the download drops to a few million rows. The archive is no longer extracted: `bulk-load.ts` streams it out of `occurrence.zip` with bsdtar (`tar -xOf`, or `unzip -p` where GNU tar is the tar), so tens of GB of text never touch the disk. `OccIndex` admits a row for a full species only if its id-hash beats the current worst, so memory stays at cap × 1.25 per species (cap 2,000 on the bulk path), and `npm run dossier` runs Node with an 8 GB heap.

**OpenAlex on a big run.** Anonymous OpenAlex requests share a per-address pool that closes after about a hundred calls and stays closed, so on the 9,000-species run every ten-minute cooldown ended in three 96-second probes and another cooldown: nine wasted hours and no literature past species 100. Two changes: `OPENALEX_KEY` in the environment (a free key from openalex.org) is appended as `api_key`, which gets its own allowance; and a host that finished cooling within the last hour goes straight back to cooling on its first 429 instead of through the slow retries. `--skip openalex` leaves literature out of a run altogether (recorded as `skipped`, and a skipped source is never the reason to rebuild), so a corpus can be built now and its literature filled in by a later run.

**Review fixes, round one (data model).** An outside review with reproductions found real faults in the model and they are fixed here, each with a test that fails on the old code. The merge rule decides a record's visibility from the timestamps of its latest delete and its latest edit, so devices receiving the same changes in different orders agree (they did not). Sync hands out batches in the order they arrived at the server, with a minute of overlap and a set of applied keys on the client, so an offline edit uploaded late is discovered (an HLC cursor skipped it); the client keeps an outbox of every change the server has not acknowledged, filled from the whole log when sync is set up, so imports and restores are pushed too (a device-id filter left them local). Storage is reserved in the vault's meta before an object is written and released if the write fails, a rejoin recounts from a listing, and vault creation is capped per address per day. Records have an opaque identity separate from the accession number (`acc`, or `no` for sowings): a number in use is refused at creation, and two offline devices minting the same number end up with two plants, the later one renumbered and told so. Places get minted ids (a second "Shelf 1" was overwriting the first), a move that would make a loop is refused, and every traversal is cycle-safe. Replace-restore turns sync off first, because a synced vault would merge straight back in.

**Review fixes, round two (honesty).** A species with no WCVP native range gets a map and a plain statement that the range is unverified, and no habitat centre, climate or cultivation: a national checklist that reports presence without native status is kept as "reported", never promoted to native. The habitat centre is the openly licensed record nearest the densest population's middle, or, when no open record lies in the cluster, the nearest tenth-degree grid point, so a CC BY-NC record's coordinates are never published as the centre; `how` says which. The growing-year rule is worded as what it is, a reading of two curves: under 120 mm there is no rainy season to read, so the cooler half is taken, and the pages no longer say the plant lives on fog or drinks it. Every sheet row now carries its own one-sentence `short`, written by the same rule at the same moment, and the note is those shorts in card order and nothing else, so it cannot contradict a card (the review's Ariocarpus reproduction is now a unit test). The plant page shows habitat and bench figures side by side with no green or red verdict. Photo credits say "observed growing wild" rather than "in habitat"; iNaturalist taxa are matched by exact name only. OpenAlex hits are title-and-abstract searches screened for the binomial (or "A. epithet") in the title or abstract, and the section is called what it is: papers naming this species. `pack-climate.py` reads each raster's own scale and offset tags, refuses to pack radiation on the tabulated value alone, has an `--inspect` mode that prints a raster's unit metadata and sample statistics under each candidate scaling, and writes the scaling used for every layer into `climate.json`. The open question it leaves: if CHELSA's raw rsds values are a daily-mean flux in W m-2 (they sit around 300 on the Atacama coast), the factor to MJ m-2 d-1 is 0.0864, not the 0.1 the grid was first packed with, a 16% overstatement of every DLI figure. `--inspect rsds 1` settles it; then `--redo rsds --trust-rsds-scale <value>` repacks the twelve layers.

**Review fixes, round four (sync).** A second review drove the outbox, the Worker and the fold with fakes and found the batch name was the fault line: a batch was named by its last HLC, the server answered "already there" for any held name, and the client acked the whole batch on that answer, so an offline edit restored beside synced changes was dropped from the outbox and never reached the server. Batches are now named `<lastHLC>-<12 hex of the sealed bytes' SHA-256>`; the server keeps each object's hash and compares, answering 200 only when it holds exactly those bytes and 409 for a different content under a held name, and the client acks only on 200. A batch the device cannot open or apply (bad bytes, a wrong key, a change naming a reserved field) is quarantined by name and reported on the sync page instead of stopping every pull behind it forever; a change list is validated whole before the fold touches it. A batch or photo the server refuses is bisected down to the item at fault, which is noted while the rest of the sync goes on. The HLC follows a peer's clock only five minutes ahead of the device's own, its counter grows to six hex digits and rolls into the wall time rather than past its width, and comparison is structural; the v2 importer cannot overflow it. Backups are checked on read (every `t` decodes; photo entries are JPEGs under the sync limit with sane names). Photos are bound to their id in the sealed data and their `sha` is checked on pull. Record ids carry the whole device id. Removing a place moves its sowings; a plant left in a removed place by a concurrent move shows at the place above; a loop between places is cut at its lowest id, which the benches page flags as needing a home. The service worker caches a navigation only when it is our own HTML, and `paths.relative` is off so a section shell works from a nested path. `SYNC_OPEN` opens sync only when it is exactly `1`. Bodies are refused from their declared length before being read; `*` and `_deleted=` are reserved field names; the vault says so when another tab holds an older version open.

**Re-deriving a corpus** (`npm run dossier -- names-big.txt --grid climate --bulk bulk --rederive`): rebuilds range, records, centre and climate for every name under the current rules, asking only the backbone (the bulk files and the local grid do the rest) and carrying photos, summary, identifiers and literature from each species' previous build with the upstream record saying so. About a second a species, so a rules change is an hour or three over the whole corpus rather than another night. The 9,000-species run that was in flight when the review landed was built under the old range and centre rules and gets this treatment when it finishes.

**OpenAlex allowance.** A free key is 10,000 credits a day at 10 a request: 1,000 species a day, which a 9,000-species run exhausts in the first hour and then refuses for the rest. So literature is not part of the long run any more; `npm run dossier -- --fill openalex` patches it into every dossier on disk that lacks it, one call each, and stops cleanly when the day's allowance is spent, saying how many remain. Ten daily runs, or about $10 of prepaid credits, cover the corpus.

**Review fixes, round three (the rest).** The forecast reducer counts each precipitation interval once (six-hourly steps were divided by six, a sixfold understatement past the hourly horizon) and splits an interval across local midnight between its two dates. Fonts: the theme asked for `Newsreader` and `Public Sans` while the packages register `Newsreader Variable` and `Public Sans Variable`, so every page had been downloading a quarter-megabyte of fonts and rendering in Georgia; the names are fixed, and the italic (botanical names) is the weight-only Latin file at 64 KB instead of the optical-size one at 147 KB. The species index is merged by key and parsed once a minute per isolate, slug resolution is a map lookup, and the front page carries each group's first 24 tiles and counts rather than the whole catalogue, fetching `/api/index` only when someone searches, filters or opens a group. A service worker caches the build and the collection-page shells at install and keeps species pages once read, with an `/offline` page for the ones it has not, so a fresh navigation in a greenhouse with no signal opens the collection.

**iNaturalist allowance.** 10,000 calls a day, three a species: a 9,000-species run crosses it around species 2,800, after which every call waits its Retry-After of about 25 seconds and the run would take four days. So photographs, like literature, leave the long run: `--skip inat,openalex` builds everything else at full pace, and `npm run dossier -- --fill inat` (about 3,300 species a day) and `--fill openalex` (1,000 a day on a free key) patch the rest in daily, each rewriting the index from disk when it stops.

**Radiation units, settled.** `--inspect rsds 1` on the real file: no scale or offset tags, `variable_unit = W m-2`, raw values around 200. So CHELSA's rsds is a daily-mean flux, the factor to MJ m-2 d-1 is 0.0864, and the grid as first packed (×0.1) overstated every DLI figure by 16%. The packer now reads the unit tag and applies 0.0864 itself; `--redo rsds` repacks the twelve layers, and `--rederive` carries the corrected figures into the corpus.

**The corpus, re-derived.** 9,471 names: 9,200 built, 255 refused as higher-rank-only (the backbone offered a genus), 16 unresolved; 26 species from the earliest small builds were not in the big list and were rebuilt separately, so the 9,226 on disk are all under one set of rules. Of them 6,919 have a habitat climate. The 2,281 without break down as: 821 with no georeferenced record at all, 833 with one or two inside the range (below the three the rule asks for), 558 whose records form no dominant population even at 4° (pantropical weeds, long coastal ranges), 68 with many records and none inside the stated range, and a handful of API-path cases. The 68 are mostly what the rule exists for (Vicia faba, Lactuca sativa, Linum, the garden Scillas: recorded thousands of times, never at home), plus a few where Kew's level-3 code disagrees with Kew's own text (Copiapoa calderana coded Chile Central, described as Antofagasta to Atacama; Mammillaria guerreronis coded Northeast, described as Guerrero). Those are applied as coded, since overriding the checklist from record density is the kind of judgement the build keeps out, and the report now flags them ("range disagrees with records") so they surface for review. The disjunct 558 are a rule choice still open: the climate at the densest population, labelled as one of several, would serve better than nothing for Bacopa monnieri, and the About page's wording would change with it.

**The API path's distributions are weaker than the files.** GBIF's per-species distributions endpoint often returns only national-checklist rows for a name the WCVP files place exactly (Coryphantha macromeris came back with nothing native). So a build without `--bulk` marks ranges unverified that the files verify, and every build should go through `--bulk bulk`; a names file with nothing in the occurrence download now skips the 28-million-row pass and takes only the WCVP files, so that costs a minute, not an hour.

**A throttle is not a refusal, until it is.** The iNaturalist fill crawled at a species a minute for half an hour with nothing on the terminal: past the daily allowance iNat answers 429 with a Retry-After and then succeeds on the retry, so no call was ever refused and the three-strike rule never tripped. Two changes in the fetch layer: a wait is printed when there is a terminal to print to, and eight throttled calls in a row to one host are treated as its quota spent (the host is cooled, the caller gets a refusal), so a fill stops itself with the "run again tomorrow" message instead of grinding.

**Reconciling the refused names** (`npm run reconcile -- bulk/report-rederive-2026-09-18.txt`): the 271 names the backbone refused are Kew's spellings the backbone either does not carry or places only at genus. For each, the script reads WCVP for the accepted name and every species-rank synonym and asks the backbone about each in turn; the first spelling it places at species rank goes into `names-reconciled.txt` under a comment naming the WCVP name it stands for, and the build runs on that list (`--bulk bulk --skip inat,openalex`; the fills patch the rest). The dossier carries the backbone's name as every dossier does, with Kew's among the synonyms. A name with no spelling the backbone accepts stays refused, and the script says so rather than guessing. `scripts/reconcile-names-lib.ts` is the pure part, `tests/unit/reconcile.test.ts` runs it on a small WCVP-shaped file.

**Synonyms are followed.** The first reconciliation run placed 72 names, and 59 of the pages it built were empty: Porrum commune for the leek, Pyrogennema angustifolium for fireweed, Narcissus jacobaea. The backbone had placed those spellings, but holds them as synonyms, and GBIF indexes records, ranges and photographs under the accepted taxon, so a page under a synonym has nothing on it. Those 59 were deleted. Two fixes: the reconciliation script now asks the backbone which species it accepts for a spelling and lists that name (or reports it already in the corpus); and the build itself follows any name the backbone holds as a synonym to the species it accepts, records the step under `upstream['gbif.accepted']`, and the species page says which name was asked for. `--index` rewrites the index from disk without building and lists every dossier that sits under a non-accepted name in `not-accepted.txt`, so the ones built before this rule can be rebuilt (they follow to the accepted species) and their old files deleted.

**Species rank means species rank.** The second reconciliation run built eight pages under accepted subspecies and varieties (Chamaenerion angustifolium subsp. angustifolium, Eriosyce curvispina subsp. curvispina four times over) because a rank test written as "contains species" matched SUBSPECIES. Deleted; the test is exact now, and an accepted infraspecific taxon reached through a synonym is taken one more step up to its species, which the `gbif.accepted` note also records. Two names the reconciliation resolved could not then be built by name (Iris orientalis, Dacrydium cupressinum): the match endpoint refuses a name with homonyms as ambiguous. So the reconciled list now carries the backbone key with each name, and a names-file line may lead with a key. `--index` found 811 dossiers in the corpus under names the backbone holds as synonyms or doubtful, built before synonyms were followed; `not-accepted.txt` lists them, the build rebuilds them by key (each follows to its accepted species), and `--prune-followed` then deletes exactly the old files whose accepted page says it was followed from that name.

**The key prefix hid the genera.** The 811 rebuild and the reconciled lists went through the API path for their ranges after all: the WCVP loader picks which genera to index from the first word of each line, and with a key in front that word was the key, so it indexed nothing ("0 names in 811 genera") and every distribution fell through to GBIF's endpoint, which for many of these knows no WCVP row. Mahonia aquifolium with 800 records and no climate was the tell. Lines are now parsed once, up front, into key and name, and repeated lines are skipped (four synonyms of one species were being built four times). The 726 species built that way today are listed with their keys and rederived through the bulk path, which carries their photographs and literature.

**Review round four: the method.** The full workup is `docs/REVIEW-ROUND-4.md`; what changed in the derivation is this. The habitat climate was read at one point, the middle of the densest population of records, and nobody who summarises a species' climate from records does that (Which Plant Where and the niche literature take percentiles across the cleaned, thinned records). It is an envelope now, dossier v2 under `s/v2/`: every in-range record placed to within 10 km is read against CHELSA one grid cell each, a cell with many records counting once, and for each month and variable the median and the 10th and 90th percentiles across those cells are kept (`climate.months` is the median year, the one the sheet reads; `p10`/`p90` the range; `cells` and `records` say what it rests on). Three cells are the minimum. Extremes and elevation are read at the typical cell, the one whose coldest night is nearest the median coldest night, and `climate.at` and `src.envelope` say so. The disjunct-population rule and the dominance test are gone: a species with two populations has a wider envelope, which the page shows. The map marker stays (densest population's middle, an open record or a cell centre, never a restricted coordinate) and decides nothing. Records with a stated coordinate uncertainty over 10 km stay on the map and out of the climate (`occurrences.nVague`). The plant page compares a bench against the median and the recorded span, which is a comparison with a range in it, not a point.

**Round four: what else the derivation got wrong.** ETOPO's "surface" is the sea floor over water, so a coastal cell averaged whole came out below sea level and every lapse-corrected extreme at Atacama, Baja and Namaqualand coasts was warmed by it; the packer masks the sea before averaging (repack `elev`), and the provider applies no lapse to a cell mean below zero and says so. Clustering bins wrap at ±180° (Fiji was two populations, a mixed median in the Atlantic) and the runner-up is the largest window sharing no bin with the winner, not the same points counted again. When an open and a restricted record share a coordinate to three decimals the open one is kept, so a licence never hides a record the map could show. A WCVP region where the plant is extinct is history, not habitat: listed as such, never a range box. WCVP names that Kew holds twice are resolved by authorship against the backbone's, and left unranged with the reason when neither matches; an accepted name outside the wanted genera (the target of a followed synonym) is found among the accepted rows instead of falling to the API. A synonym whose accepted taxon the backbone cannot serve is refused, not published as the synonym. Wikidata is matched by GBIF key (P846), never by the first search hit; MediaWiki's HTTP-200 error bodies are errors; a refused second page of occurrences is a refusal of the sample, not a smaller success; a refused WCVP call is `climate: refused`, not "no WCVP entry"; a fill that hits an error records an error and leaves the section alone. Carry-over: literature, summary and photographs per source (Commons kept when iNat refused), and the range, records, marker and climate as one snapshot when a core source refuses, never piecemeal, and never across dossier versions. The front page's region grouping unwraps antimeridian boxes and has Oceania, Siberia and Antarctica. `parseName` reads `cv.`, a bare genus on the right of a cross, a nothogenus written `xGraptoveria` and an apostrophe inside a cultivar name; a nothospecies slug keeps its cross; two dossiers with one slug get the later key appended in the index. The fetch layer honours a long Retry-After by cooling the host for that long instead of waiting thirty seconds, reserves a pacing slot before waiting, and calls eight throttled calls in a row what they are.

**Round four: the pages.** Every sentence on the species page, the sheet and the plant page is now one of four things: a figure with its source, a labelled reading of a curve or rule, a quoted and credited source, or the method's fixed wording saying what was and was not derived. The archetype prose and every sentence that said what a plant does or wants or what to do to it are gone; an archetype is one figure (a group minimum) with its table named. Refusals are shown as refusals on every section, the front page and the plant tile; an unreachable index says the reference could not be reached, not "not in the reference". Both runs of a bimodal season are printed, from one function, on sheet and label alike; a flat temperature curve with sharp rain says exactly that; the cold floor names which quantity it is and the 4 °C clamp is gone; the forecast promises nothing beyond the hours it covers. Kew's own life form and climate class are quoted with credit. Contrast, labels, headings and colour-only meanings were fixed to WCAG AA; the browser talks to `/api/names` on this site for the species picker, and the image hosts it does load from are named on the About page.

**Round four: the data path.** The GBIF download is requested as a DWCA, not SIMPLE_CSV: the archive then carries `multimedia.txt`, every photograph on the records with its own licence and creator, and iNaturalist's research-grade wild observations are among them. A second pass over that file, for the observation records the first pass marked as carrying images, serves the builder through the same media adapter the API path uses, and GBIF media is asked for first when the files supply it. The iNaturalist fill then asks only for what the download cannot have: the cultivated set, and the wild set for species with fewer than six photographs. The download's DOI is written on every dossier's occurrence record and the bundle's citation sentence is true. `coordinateUncertaintyInMeters` and `mediaType` ride along in the compact rows.

**The species page, read the way a grower reads it.** Sections ran in derivation order (summary, climate, habitat, cultivation); they now run in reading order: what it is, what it wants, then the evidence. Cultivation sits under the summary with the condensed note first, the cards under it, and the grower's own notes as one line until there are any. The Wikipedia lead is quoted to four sentences (a splitter that knows `subsp.`, `var.`, an initial and `et al.` are not sentence ends) with a link where more followed, never a mid-sentence cut; a stub stays a stub. The climate is drawn before it is tabulated: a climograph (`src/lib/climate/climograph.ts` is the geometry, pure and tested; `Climograph.svelte` places it), day and night medians as lines with the 10th–90th percentile across the habitat cells as a band around each, rain as bars with a whisker for the same span, the cold quarter shaded, a dashed frost line only when the axis crosses zero, POWER's absolute minimum and 99th-percentile day as ticks under the coldest and over the warmest month, DLI and RH as two sparklines beneath. Axes are per species, so a Lithops and a Tillandsia each fill the frame; a one-cell species draws no band and the legend says so; a month under a millimetre draws nothing and a habitat with none says so in words. The chart is drawn at the width it is shown at, so labels do not shrink on a phone, and the `<desc>` carries a plain reading of the same figures. The month table stays under a "Figures by month" disclosure. Nothing is smoothed and nothing is drawn the dossier does not carry.

**Species is your list, once you have one.** The front page had been the whole catalogue with a "you grow" chip; for a visitor that is the reference they came for, for a grower with eighty plants it is a wall of other people's plants. So it switches: with nothing in the collection it is the catalogue as before (server-rendered, so crawlers and first visits see it); once anything is grown or followed it is your species, the kinds you grow and the kinds you are keeping an eye on, with a search box over the whole corpus at the top and a link to browse all of it. A species can be on the list without a plant of it: `followed` on the taxon record (the one that holds your notes), set by a Follow button on the species page, synced like any other field. `src/lib/db/species-list.ts` is the list logic, pure and tested.

**The download's photographs never reached the pages.** The DWCA came down (12 GB, `10.15468/dl.3h4zam`), the loader read `multimedia.txt`, and the rederive still wrote `0 photograph sets from the files`: a re-derivation skips every network extra and `gbif.media` was on that list, with the previous build's photographs carried over whole. Two fixes. A rederive with a download that carries media now reads it (it is a file, not a network call) and merges: iNaturalist and Commons keep their places, the download's GBIF set replaces the old one. And `--fill gbif --bulk bulk` does the same for every dossier on disk in one pass over the archive with no API calls, which is the right tool after a new download: an hour, not a rederive. A species the download has nothing for keeps what it had, because the download having nothing is not the API having had nothing. Six or more wild photographs from the download mark the iNaturalist wild set as not needed, so the next `--fill inat` asks only for cultivated sets. GBIF attributions now say "CC BY", not "BY".

**Fewer species got photographs than the index held.** The first `--fill gbif` pass reported 6,786 species with photographs in the index and gave 4,084 dossiers a set. Two reasons. The occurrence pass attributed a record identified to a subspecies (taxonKey the subspecies, speciesKey the species) to whichever key it iterated last, the subspecies, so its images were indexed under a key no dossier has; the owner is the species key now. And the index counted images before the licence check, so a species with only CC-BY-NC images counted as having photographs it was never going to be served; the licence is checked at the index, and the count is a count of open ones. The fill is rerun on the same archive.

**Round five, phase one: the page's word.** The findings are in `docs/REVIEW-ROUND-5.md`; this is what changed so that every figure on a species page is what its sentence says. The typical cell's position is the cell's centre, computed from the grid index, never a record's coordinate (a CC BY-NC record had been reaching the page as `climate.at`); the cell-centre snap in `geo.ts` compares at three decimals, because `floor(x·10)/10 + 0.05` is not `x` in floating point for a third of the tenth-degree centres and a restricted record could sit on the "centre" unnoticed; and the marker's middle moves to the window's fullest bin when the window's median falls in a bin less than half as full, so a stray record between two populations is not where the marker lands. Frost is kept as a count (`frostNights`) beside the rate, and one function words it for the sheet, the glance tile and the chart, so one night in forty years is "1 frost night in 40 years" everywhere and never "no frost". The Rain card's annual range is the 10th and 90th percentile of each cell's own year, carried from the provider as `climate.annualRain`, not a sum of monthly percentiles (three cells at 120 mm had read "0 to 288"); the Light card's spread says what it is. Seasons: a wet season within half a degree of the year's mean is called neither winter nor summer; under 120 mm the cooler six months are named only when at least a degree cooler than the other six, else nothing; and months are shifted for the other hemisphere only where the temperature curve gives a season to reverse (not a flat year, not within 10° of the equator), which the sheet, the note, the label and the plant page all follow. The lapse provenance says what was done in every case and the Temperature card's `why` follows it. The archetype line says when the table holds no figure for the group (four of eight groups). The Wikipedia quote's splitter knows citation tokens (`Sp. Pl. 1753`, `Cact. Succ. J.`, `z. B.`) and counts a sentence that starts with any script's capital. The climograph's extremes are marks at the panel's right edge, labelled undated, not ticks under a month; the legend names the cold quarter and the DLI/RH strip, the strip has its own hues, and the `<desc>` takes day and night ranges from their own series. A skipped source is "not asked", never "none", on the hero and the pills; a refused occurrence source is "not checked" on the record map; the world-map caption claims a climate only when there is one, and the marker's `how` no longer says anything about the climate; the note says which kind of absence the climate is. The glance tiles are "warmest month, mean day" and "coldest month, mean night" with the POWER extreme on its own line, sourced. The front tile says "open records". WCVP homonyms are resolved by authorship before the accepted-row preference, and the download path carries `degreeOfEstablishment` so a cultivated record is dropped on both paths. The export README names `cool` and `by-sa`. `--rederive` writes the two new dossier fields; until then the page derives the frost count from the rate and omits the annual range.

**Round five, phase two: the collection keeps what it is given.** Every write goes to the vault before it goes to memory: `commit()` appends first and applies only on success, and a failure sets `collection.lastWriteError`, which the plant list and the plant page show as "This change was not saved". The sync quarantine is narrowed to what it was for: a batch that cannot be decrypted or validated is set aside by name; a batch the vault could not store aborts the run, is not marked as had, and is fetched again next time (the same for a photograph whose blobs could not be written). A change stamped more than five minutes beyond the receiving device's clock is held: stored in the log, not applied to the state, re-folded when the clock reaches it, counted on the sync page, with a warning when this device's own last stamp is ahead of its clock; a fast phone can no longer lock a field on every device until its clock's date. The v2 importer stamps each record from the file's own modification time and skips ids already in the log, so importing the same file twice changes nothing. "Replace from backup" writes the whole file into a staging database, verifies the counts, and only then wipes and copies in, with a flag in the vault's meta that makes `openVault()` finish an interrupted copy; a failure before the switch discards the staging database and leaves the device as it was. An export names the photo records whose pixels were not on the device (`manifest.photosMissing`), counts only the photographs it holds, and says so before the download and after a restore. The numbering scheme is a synced `setting` record, so two devices mint numbers the same way, and the duplicate-number repair is deterministic from the merged log, so both devices renumber the same plant to the same number with one note. The pull cursor is `(uploaded, key)`, so 501 batches in one second cannot repeat for ever; an open idle device pulls on focus, on becoming visible, and every five minutes. A full vault is 507 with the figures, shown as "Your vault is full", not bisected into a request storm. A batch is named by the hash of its plaintext, so a re-push after a lost reply lands on the same key, as the formats page said. The sync and formats pages say what the server can see (devices, timing, photograph count and sizes) and what it cannot (anything about the plants). A location that is its own parent is cut and flagged, and a cut node falls back to its pre-move parent. Following a removed taxon record clears the removal. A merge restores the file's numbering scheme onto a device still on the default. The plant list keeps a storage-not-persisted notice with a back-up link. In the build, deduplication at one coordinate prefers the more precisely placed record within a licence class, so a 1 km record is not lost to a 100 km one that came first.

**Round five, phase three: the server before strangers.** The storage allowance is a per-vault byte counter in KV, refused at the limit with 507, resynced from the R2 listing on vault open and once a day, with a per-address daily byte cap beside the vault-creation cap, and vault creation fails closed when the KV binding is missing rather than letting everyone in. A new vault's id must be the one its token derives (the server does the derivation at the one moment it sees the token), so a vault cannot be registered under an id that is not its own. Push, pull, listing, creation and the name proxy are rate-limited per address with a fixed window kept in isolate memory and folded into KV; a refused request is a 429 with `Retry-After`, and the sync engine reads that header and comes back then, instead of noting the item as refused. `meta.json` is a lazy snapshot (every 16 MB or 30 s) rather than a write per object, which R2's one-write-a-second rule was going to refuse on the first push of a photographed collection. A pull lists at most twenty pages of the vault's prefix; a vault past twenty thousand batches is told so rather than listed short. `/api/names` answers 502 with `no-store` on any upstream failure or a body that is not an array, takes only characters a plant name has, and is rate-limited; cache hits are served before the limit. HTML is cached for a minute with no stale-while-revalidate, and SvelteKit's version poll reloads an open page on its next navigation after a deploy, so a page never imports a chunk the previous build had and the new one does not; the service worker no longer takes over under open pages with `skipWaiting`, precaches each file on its own so one bad shell does not fail the install, and says in the console when it could not register. In the fetch layer a 403 strikes and cools a host like a 429 (a blocked host asked three thousand more times is a ban), and a Retry-After date already in the past is floored to the backoff instead of read as "now, five times".

**Round five, phases four and five: the flows, the text, the quality list.** The species picker is a combobox: arrows move a highlight, Enter picks it without submitting, Escape closes, Tab keeps the pick, and Enter on a name that matches nothing asks once before it files a plant under exactly what was typed. A sowing's seed count is required and never defaults to twenty. The forecast route answers 502 when MET Norway or the weather service does not, and the bench and frost pages say "Forecast not checked", not a red "500". The Species tab keeps a hint in local storage so a returning grower sees a skeleton, not the catalogue and "You grow 0", for the half-second before the collection loads. Tap targets in the top bar, breadcrumbs, section tabs, log-entry removal and the footer are forty pixels, and the smoke test measures them. The top bar and section nav are opaque. Missing spaces, plurals and a doubled licence in photo credits are fixed, with one `plural()` helper. Quality: `idHash` folds the high word in, so GBIF ids past 2^32 (2024 onward) hash distinctly and the record sample is the uniform one it claims to be; the photographs a download supplies are the same hash sample, not the first forty in file order; a wanted subspecies owns its own photographs when its species is not wanted; a rederive keeps each carried refusal's original reason; `quantile`, `r1`, `KewDescription`, the cultivated-record pattern and the month names each exist once (so the record filter now also drops records flagged naturalised or invasive, as the range rows already did); the corpus export takes the habitat latitude from the marker first, as the page does; the `as never` casts in the build script are gone; `envelope()` has a unit test and the planted frost night is asserted; `within()`, the unused `stock` and `task` kinds and `Change.m` are gone; the vault waits for in-flight writes (up to five seconds) before reloading on a version change, and a photograph's pixels and record are written under one hold.

**`--offline`: a re-derivation that asks nothing.** The round-five rederive spent most of its day waiting on GBIF's backbone (a 429 with a three-second Retry-After on two species in three), for calls that fetch the name, its synonyms and its vernaculars, none of which a re-derivation changes. `--offline` (which implies `--rederive`) carries the previous build's name block through a new `taxon` option on `buildDossier`, answers the bulk fetcher's one lookup (a name's authorship, for WCVP homonyms) from the previous dossier, lets NASA POWER through because the extremes cache is on disk, and refuses every other upstream as "not asked: offline re-derivation". The upstream records of a carried block say so. A key with no previous dossier is reported and skipped, since there is nothing to carry. The range, records, marker, climate and the download's photographs are all rebuilt from the files and the grid, so a rederive is now the files' pass alone: an hour, not a day, and indifferent to GBIF's mood. A build by name never carries; it asks the backbone.

**Deploy prep.** `docs/DEPLOY.md` is the checklist: bucket, namespace and the KV id pasted into `wrangler.jsonc` once; an R2 spend alert before the first upload; the corpus to `s/v2/` with `rclone copy` (incremental, so a daily fill is a fill, an index and one command); `npm run deploy` for every release; the hand checks after the first one; rollback. `static/.assetsignore` keeps `s/` out of the Worker's static assets, which was going to be nine thousand files uploaded on every deploy and served from the wrong place; the Worker reads the corpus from R2 and falls back to assets only for the fixture corpus. `SYNC_OPEN` is a declared var, `DOSSIER_V` is not an env any more (it is the schema constant), and the README says where the deploy doc is.

**The offline pass refused what the download never had.** The first `--offline` run over the corpus wrote 1,407 species with `gbif.occurrences: refused` and a refused climate, Acer rubrum among them. The download request leaves species above the record cut to the API path (`bulk/api-path.txt`, 233 of them) and had nothing for another thousand-odd keys, and a dossier keeps only its open records, so there was nothing on disk to re-derive those from; offline refused the API and the climate went with it. An occurrence search that reaches the offline fetcher has already fallen through the bulk fetcher, which is the one case the files cannot answer, so it is now let through to the API, and only it. The affected species are listed by `report.txt` and rebuilt with the same flags over that list; the index is regenerated from every dossier on disk as always.

**The catalogue as closed rows, and a menu.** Nine thousand tiles grouped by origin was a wall, and a phone painted every one. The front page is now rows: grouped by genus by default (what a grower thinks in), by origin (the little map stays) or by family, every row closed to its name, family or genus count, species and climate counts and one photograph, with an A–Z bar for the alphabetical groupings. One row is open at a time and it is the URL (`?by=genus&open=copiapoa`), so a link lands on it, the back button closes it, and the page works without JavaScript; the server sends the rows and only the open row's tiles. A search or a chip flattens the catalogue into the matches across every group, alphabetical, so nothing hides inside a closed row; that is the one path that fetches the whole index. The header lost the tagline and half the welcome card, and "You grow 0" is not offered to someone who grows nothing. The mark in the corner is a menu that reaches everything (the five places, labels, backup, sync, the about pages, the source) from any page, a panel under the mark on a desktop and a sheet from the left on a phone; Escape and navigation close it and focus returns to the mark.

**After the first deploy: what a visitor gets in the first minute.** Six changes, in the order a new visitor meets them.
