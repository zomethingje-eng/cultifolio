# Review round forty-nine: three reviews, one build

Three reviews read together: my own deep pass after round forty-eight, the first reviewer's round thirty-five (findings 1–7, U1–U8, S1–S2, D1–D4, P1–P4) and the second reviewer's round twenty-seven (P1 1–3, P2 4–6, P3 7). Every finding was checked in source before it was taken; what was not taken is at the end, with the reason. The numbers below group the work by layer, not by reviewer: 1 is the data, 2 the server and the catalogue, 3 the flows and the screens. "R1" is the first reviewer, "R2" the second.

## 1. The data

1. **The written number never beats a person's** (R1-1; D1). Round forty-one's load wrote `acc` or `no` as a change stamped *now* on every record of the oldest shape, so a renumbering made on another device while offline, and arriving later, lost to a machine's reading of the record. The change is stamped one millisecond below the record's oldest change (`hlcBefore`), where any edit to the number, by anyone, before or after, outranks it; a record whose log already holds a number change (held, say) is left alone, and so is an incomplete one. Tests in `vault-store.test.ts` fail against the old code on all three.
2. **Holds are judged by the server's clock, not the device's** (R1-2 of the data findings; my own). A phone set to 2031 stamped every change six years ahead, judged them against its own clock and saw nothing wrong, while every other device held them all until 2031. `hlc.ts` now carries an offset: the sync engine folds in the `Date` header of every pull (`trustServerTime`), the offset moves only past thirty seconds of disagreement, and `nowMs()` is what stamps are minted from and holds are judged by. A device that never syncs keeps its own clock. The sync page says when the correction is on and by how much. Tests in `log-hold.test.ts`.
3. **An edit made while a peer's change to the field is held keeps the field** (own). The fold notes each held stamp under its field; a local edit to that field is stamped past it, as it already was past this device's own ahead stamps, so the person's edit is not overwritten when the held change comes due. Test.
4. **One sync run per browser** (R1-3 of the data findings). Two tabs each pushing and pulling the same vault wrote the sync record over each other; the run takes a Web Lock, and the other tab's run is tried again when it is free.
5. **What belongs together is written together** (D2 in part; own). A death was its line and then the status; an archive the status and then its line; a batch and then the line on its parent; a photograph's removal and then the cover's clearing; a move and then its line. Each was two commits, and a page closed between them left half. `addEventWith` and `movePlants` write each pair in one commit; `addSowing` folds the parent's line into the claim. Tests in `collection-store.test.ts` hear one commit and see a refused vault keep both halves out.
6. **A removed photograph's bytes go** (R1-4 of the data findings). The pixels stayed on every device and the ciphertext on the server for good, counted against the vault. A device that folds the removal drops its pixels; ten minutes on (past any Undo) one device asks the server with `DELETE /api/sync/photo/<id>`, which takes the bytes off the count and answers 404 when already gone; the id leaves `photosPushed`, so a record brought back later is pushed again from a device that kept the pixels. `deleteCounted` with tests; an engine test walks two devices through it; `/about/formats` says so.
7. **A replacement from a file with unreadable changes is refused** (R1-5 of the data findings). A merge leaves a change this build cannot read in the file; a replacement is the file and nothing else, so the same change would be gone for good, and a backup from a newer build is the file most likely to hold one. `replaceThroughStaging` refuses with the first such change named, and the page says to merge instead. Test.
8. **`events.csv`** (own). The years of waterings, repottings and measurements were in the changes file only. The backup carries the timeline as a sheet, oldest first, with the plant's or batch's number and species. Test; the formats page and the backup page say so.
9. **The sorted lists and the place tree are built once per change** (own). `accessions`, `locations`, `sowings`, `taxa` and the shown tree were rebuilt on every read, and the plants list, Today and the search read them several times a keystroke; each is a `$derived` now, as the events-by-plant index already was.

## 2. The server and the catalogue

1. **The page cache key carries the build** (R1-3). A page held across a deploy named chunks that were gone for up to a minute. `version` is in the key.
2. **`?was=` pages are not held** (own). The query is anyone's to write, and each spelling minted a copy; the species page is rendered every time it is reached by an old name.
3. **The home page's queries are reduced before they key a copy** (R2-3; R1-4). `open` only when it names a row of that grouping, `at` only a whole number inside the catalogue, `from` only a letter the catalogue has, `by` and `chip` to their known values: a link with an unknown `open`, a tracking tag or a capital shares the plain page's copy rather than minting one. The page reads its query by the same rule, so `browse` is judged on the same reading. Tests in `hooks.test.ts`.
4. **`Vary` on a held copy; a cache that fails is a page rendered** (R1-6). The stored copy drops `vary` for the Worker's own key; the reader's copy carries it again. `match` and `put` are caught.
5. **A deep `?open=` link starts near its row** (R1-4; R2-2). A link to Welwitschia sent the whole catalogue to reach row 1,300. The window starts fifteen rows above an opened row beyond the first sixty; the rows above come through "Earlier" and the upward fill. Test.
6. **The upward fill runs only while the reader is within the rows** (R2-1). Round forty-eight corrected the scroll only when the first row sat above the pinned edge; after a jump to W it sat just under it, so the chunk above pushed W down, the sentinel came back into reach, and the fill ran to A and landed there on the live site. The rule is a pure function (`fillBefore`, tested): the fill runs on its own while the first loaded row is at or just under the bar, never from the chips or the letter index above the rows (after A–Z); and the correction holds the row itself in place, by its element, whatever its position. A scroll listener joins the observer, since the observer fires on a change of reach and not on every scroll. The "Earlier" link is sixty rows back, as the server's window is. e2e at a short viewport: no fill while the chips are on screen, the fill once the rows are under the bar, the row that was looked at unmoved.
7. **A window from another catalogue is not spliced in** (R2-3). `/api/rows` answering from a corpus replaced since the HTML was rendered (a different row count), or a fetch begun before the server's window was replaced, lands nowhere; the link then navigates.
8. **No horizontal scroll from the unrendered sections** (R2-4). `contain-intrinsic-size: auto 480px` gave them a width too; height only now.
9. **Two tiles at high priority** (R2-5); **`floorHeld: false` is not written unasked** (R1-6): "bottoms out" is the unset reading as well, so an unrelated edit to a place that never said does not say for it.

## 3. The flows and the screens

1. **Water is one tap, with Undo** (U1). On the plant page the Water button writes a watering today and the toast takes it back; a dated watering, or one with a note, goes through Log, whose type can be set. The plants list has a Water button on each growing row, so a bench is watered without opening a page. Today's not-watered line has "Water these N" with Undo, as a place's "Water all" has. e2e.
2. **Archive and Mark failed ask once; Remove batch asks and can be undone; Mark failed can be undone** (own). e2e.
3. **Move plants here** (own). A place page takes plants in from a ticked list, filtered as typed, in one commit, each with its move line. e2e.
4. **The short Add form** (U3). Species, place and date; the rest under "More", which stays open once opened. The actions are pinned above the tab bar on a phone, "Save and add another" keeps the place, date, source and provenance for the next plant, "Add as typed" is the second press's own label, the "+" in the top bar is not shown on the add page itself, and an in-app move away from a half-filled form asks first.
5. **The search box stays on the device in three more cases** (R1-2). Before the collection has opened (a grower's first keystrokes were going to the server while the view was still unknown), while the text matches one of their plants, and when it is shaped like a plant number, nothing goes to `/api/search` or into `?q=`, on either view. e2e; `/about/how` says so, and names `/api/rows`.
6. **Today** (D3, D4, U4; R2's recommended line). The not-watered line says how many of those plants are in their habitat's dry season by the species sheet (the growing-year rule, shifted to the grower's hemisphere): a fact about the habitat beside the fact about the record. The photograph line counts records older than six months, not a plant filed today. A "Kept on this device" line says the last backup's age, sync's state and records waiting, with a Hide that Settings undoes. "Frost watch needs a site" offers "use my location" in place.
7. **The audit** (U-items). Tick all and Clear; the count of ticks; Cancel with ticks made asks first; the result stays under the list until the next audit; "never audited" is said only once the place has had an audit.
8. **The key card** (U6). Each group of the key is one unbreakable piece; the type-back sits under the key it asks about; a fresh key survives a reload of the tab (kept in session storage until Start syncing or Cancel).
9. **Labels** (own). From the menu, every growing plant is picked when they fit a sheet or two (twenty-four); past that nothing is, and "Pick all shown" is one tap. The Year numbering scheme applies on the tap; Prefix waits for its letters.
10. **Phones** (U2, U5, U8). Every text field is 16 px, so iOS does not zoom in on focus; the toast sits above the tab bar, under the thumb; tab labels are 11.5 px in the second ink; the remove, sort and undo controls are 40 px.
11. **The species page** (S1, S2). "In short" is open from the start; a failed photograph's line takes the photograph's own 150 px box on a phone. Two captions said "This species' habitat figures, with their source" on two cards; Light and Warmth now say which. The Related line begins with a capital.
12. **Words** (own). "Location" is "place" on the places pages; "Sow here" is "Start a batch here"; the tab bar says "My plants" as the top bar does.

## Not taken, with reasons

**Units rendered on the client** (R1 P2, R2-6): the edge and the Worker cache are the same per-colo store, so a units-free page would save one render per colo per minute per units value, against a flash of the wrong units on every first paint; left until measured. **`data-sveltekit-preload-data="tap"` on species links** (P3): `hover` already preloads on touchstart; nothing to add. **The search above the featured strip** (U7): the search row is the pinned head of the list, and the strip would then sit between the letter index and the rows; the visitor's sentence under the title says what the site is. **Font subsetting** (P1), **CSV import**, **vault compaction**, **a wire change for atomic creates** (D2 in full): as before. **The Show HN draft**: the author's.
