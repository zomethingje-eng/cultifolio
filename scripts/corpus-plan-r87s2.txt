# Round eighty-seven, stage 2: one walk for the whole round's data, then the fills that need the walk's pages, the
# index, the checks, the upload and the live check. The stage-1 data fix (summaries left for --fill summaries, the pages
# an offline build did not derive again, the round's own pages) is folded in, so the download is read once.
#   node scripts\corpus-step.mjs --plan scripts\corpus-plan-r87s2.txt
# Before it: the new bulk files in bulk\ (docs\STAGE2-OWNER-87.md, steps 1 to 3). CITES is optional here: until the
# owner's check (that file's step 4) sets the table's "# checked:" line, every page's CITES line says "not asked".
# Not in this plan: --fill flowering and --fill bhl, which run for days within their daily allowances; they are
# scripts\corpus-plan-r87-daily.txt, run once a day after this plan has uploaded.
#
# Why this order:
#   - The walk derives every page again offline under this round's code and, with --bulk, reads Kew's names, the four
#     sourced facts and Kew's citations and parents for the pages it builds. It carries each page's summary,
#     identifiers, iNaturalist taxon and the fills' fields from the dossier on disk, so the online steps come after it.
#   - --list-offline reads the dossiers the walk wrote, so it comes after it; the one online --keys build then builds
#     its list, the summaries left and the round's own pages together (a list that is not there names no page).
#   - --fill kew-published and --fill sources run once more over every page after the --keys build: a walk that stopped
#     and resumed ran them only on the pages of its last part. Each is offline and writes nothing a second time.
#   - --fill elsewhere reads each page's own Wikidata item, so it comes after every build that can change the item.
#   - --index comes after every step that changes a page; the three checks and the listing read the index's corpus.
