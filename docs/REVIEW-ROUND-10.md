# Review round ten: `9086b10` re-reviewed, triaged

The reviewer of rounds eight and nine re-read the round-nine build against its own stated rule (the collection never leaves the device except through encrypted sync) and found that the round-nine fix had closed one channel and left another open, and that the resolver added there could damage a record. Four findings, all confirmed in the source, all fixed here. One further defect surfaced while running the suite and is item 5.

1. **The labels still sent the grower's species to the server, by key** (R10-1; the reviewer's one-thing-to-fix). Round nine moved the index lookup to hash buckets, but the labels page and the plant page then fetched `/api/dossier/<key>` for each plant: a list of GBIF keys is the species list, one request per species. Gone. The reference now serves `/api/sheets?b=…` (`src/lib/server/sheets.ts`, `src/routes/api/sheets/+server.ts`): for each bucket asked, the sheet of every species in it, where a sheet is what a plant page, a label or a batch reads of its species and nothing else (name, family, thumbnail, the marker's latitude, the median year to a tenth, the 10th and 90th percentile night and light, the extremes, the counts, or the refusal). The device asks by bucket and picks its own species out of the answer (`sheetsFor`, `sheetForName` in `src/lib/ui/index.svelte.ts`); the labels page primes every bucket its picked plants need in one request. The buckets are now 32 rather than 256 (`src/lib/core/bucket.ts`: FNV-1a modulo 32), because at 256 a bucket of thirty-five species narrowed a plant to one in thirty-five; at 32 it is one in 280, and the answer is still 75 KB gzipped (2 KB a species raw). The cost is stated plainly: a plant page now fetches 75 KB where it fetched an 11 KB dossier, and a collection spread over twenty buckets fetches 1.5 MB for its labels the first time, against 300 KB by key. The edge keeps each bucket for a day and the worker keeps it for the build (item 4), so the second visit costs nothing and works in the greenhouse. `/api/dossier/<key>` still exists for the species page, where the visitor has already opened that species by name. `/about/formats` now describes this channel: the server sees which buckets a device asked for, and no more. e2e: the labels test records every `/api/` request the page makes and asserts one `/api/sheets?b=` call, no key, no slug, no name.
2. **The resolver overwrote a subspecies' key with its species' key** (R10-2). Round nine's `dossierForName` compared the fetched dossier against the record's name through `speciesSlug()`, which maps *Ariocarpus retusus* subsp. *furfuraceus* to its species; a subspecies with the right key therefore looked wrong, and the repair replaced its key with the species'. The repair now runs only for a name at species rank (`speciesOf(name) === name`) whose stored key differs from the sheet's; a name below species keeps whatever key it has, and reads its species' sheet for the figures, as before.
3. **The import day was known to one device** (R10-3). Round nine wrote `importedOn` into the device's own `meta`, so a plant imported on the laptop counted from years ago on the phone. It is now a field on the record (`importedOn`, typed on `Accession` and `Sowing`), written as a local change when a file is ingested for a record whose id carries no time, so it syncs like any other field and every device counts from the same day; it is written once, and a later file for the same record does not move it. Store test: the field is in the log, a second device that receives the log reads the same day, a second file does not stamp it again.
4. **The plant page fetched its species twice** (R10-4). The effect that loads the sheet keyed on the record object, which the store replaces on every change, so each edit refetched. It now keys on the name, key and parentage (`askedFor`), and the reference files (`/api/dossier/`, `/api/entries`, `/api/sheets`) are served cache-first by the worker within a build, so a page that has the file never asks again; a new build starts a new cache.
5. **A device that had just joined a vault said "Synced" before its first pull** (found by the suite, not the reviewer: the late-upload sync test failed on a cold server because the status card read "Synced" while the first batch was still downloading, and the test moved on). `setup()` in `src/lib/sync/engine.svelte.ts` is busy ("Joining…" or "Starting…") from the moment the vault answers until the first run takes over, with no tick in between where the card can say "Synced" with nothing pulled.

## Set aside

Nothing. The one open choice is the bucket count: fewer than 32 would hide more and cost more per page; 32 is stated on `/about/formats` and is one constant to change (`BUCKETS`, and the `BUCKET` pattern beside it).
