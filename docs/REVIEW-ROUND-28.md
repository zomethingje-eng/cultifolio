# Review round twenty-eight: two reviews of `7a99f9e`, triaged

The second reviewer's nineteenth pass (two findings, one of them a regression the round-twenty-seven fix made) and the first reviewer's round twenty-seven (fifteen findings from a walk through propagation, backup and the phone's first screen, plus a list of things they say stayed open from a round-twenty-six review that never reached this repository). Every finding was checked in the source or reproduced; the "still open" items were taken as claims and each was tested here rather than assumed. "R1-n" is the second reviewer's; "R2-n" the first reviewer's; the still-open list is "R2-0".

## The regression

1. **Medium and container were never saved by a batch edit** (R1-1, R2-1; both reviewers' one thing to fix). Round twenty-seven's fix for the vegetative provenance put its comment at the end of a line that went on: `provenance: …, // a batch edited from cuttings … medium: f.medium.trim() || null, container: …` swallowed the two fields that followed on the same line, so every batch edit since `7a99f9e` dropped them. This is the same class of slip that bit round twenty-four (a comment inside a one-line expression), and it is the one `svelte-check` cannot see, since the line is valid. Each field is on its own line now, the comment on its own; the e2e edits a batch's medium and container, reloads, and reads them back. The same test would have failed against `7a99f9e`.

## Backup

2. **A backup of more than about a thousand changes never finished** (R2-0, verified and reproduced). fflate's asynchronous `zip` hands any entry of 160 kB or more to a worker it makes from a `blob:` URL, and its `unzip` does the same for entries over 512 kB; the site's CSP says `worker-src 'self'`, so the browser refuses the worker, and fflate's error path does not fire, so the promise never settles: "Take a backup" showed a spinner for good, and a restore of such a file the same. Small backups passed, which is why forty rounds of tests never saw it. The writer and reader are the synchronous ones now (a few megabytes deflate in well under a second on the main thread, and the photographs were already stored uncompressed), and the CSP stays as it is. e2e: four hundred plants with a kilobyte of notes each, merged from a JSON export, backed up, the store wiped, the zip restored; the test hangs at the download against the asynchronous writer and passes against the synchronous one.
3. **A value of the wrong type in a change could throw on every page** (R2-0, verified in the source: a batch's `sown` stored as a number throws in Today's sort, and the front page with it, on every load). Changes from outside (a pull, a file) were checked for shape but not for the type of their values. The log module now carries the type each known field takes; a change whose value is of another type is refused before the fold, with the field, the kind and the value named, and the batch or file is refused whole as any bad change is. A field this build does not know still passes, so a newer build's records sync to an older one. The v2 importer, the one place a stray type could come from in practice, writes a number typed where text belongs as text (a price of `12`), drops values of any other type, takes a plant number typed as a number as the same number, and skips a second plant under a number already in the file, saying so in the report (R2-0's "numeric number" and "duplicates"). Unit tests for each.

## Propagation

4. **Switching a batch to cuttings dropped its seed source, lot and provenance** (R2-2). They are kept whatever the method and hidden while it is vegetative, so a switch by mistake loses nothing on the way back; only the provenance follows the method, since `veg` is what a vegetative batch is. e2e: seed fields hidden under cuttings, back under seed with their values.
5. **A batch with no count yet showed 0 %** (R2-3). The rate is `–` until a count exists; the fourth card already said "not counted yet" and the two now agree. Unit test and e2e.
6. **"Lot / field number" was one box, and a pot-up carried whatever was in it as the plant's field number** (R2-4). A seller's lot code is not a collector's number. A batch has `fieldNumber` (the collector's, carried to every plant potted up as its own) and `sourceRef` (the lot, carried as the plant's reference); the add and edit forms have two boxes; the header shows each set off with its separator, which also fixes "Kakteen Haage· lot" (R2-14: the space at a Svelte block's edge was trimmed); the formats page and its test list the field. An older batch's lot is no longer copied into `fieldNumber`; a grower with a field number in the old box moves it with one edit. Unit test: the potted plant has the field number and the lot in their own fields; e2e the same through the pages.
7. **The batch edit form believed what it was told** (R2-5). A start date after today, or after the batch's first log entry, and a started count below what has been counted are refused with a sentence under the form. e2e for the first and the third.
8. **A potting or a loss could be dated before anything was counted** (R2-6). Both are refused before the first count that found anything up. e2e.
9. **Today said "sown" for a batch of cuttings** (R2-10). It says "started" for a vegetative method. **Mark done with plants still in the pot asked nothing** (R2-10): it asks first, naming the count, with "Mark done anyway" and "Keep open". e2e. Removing the "Marked done" line from the log leaves the status as it is, which is by design: the line is the record of the change, the pill is the status, and Reopen is the way back; the reviewer's expectation is noted and not taken.
10. **`batches.csv`** (R2-9, part). The backup carries one row per batch with the figures the batch page shows (started, latest count, potted, lost), the lot and the field number apart, and the place as a path; the formats page lists it and the test reads it back from a zip the writer built. Tray labels for batches are deferred (below).

## The pages

11. **The layout moved focus to `<main>` on the first load of the session** (R2-11), so a screen reader began mid-page, and every page read as having done something on arrival. `afterNavigate` with no `from` is the first load; focus is left where the browser put it. In-app navigations still focus the content.
12. **Both navigation landmarks were labelled "Places"** (R2-12), a leftover from when the segment control was the places tabs. "Main" and "Tabs".
13. **A phone's first screen had the pictures and not the way in** (R2-13). The "New here" line (add a plant, bring in a collection) sat under the featured grid; it is above it now, so the pitch, the count and the two actions are on the first screen.
14. **Smaller things** (R2-14). `/privacy` redirects to `/about/how#privacy`. The failed-photograph caption no longer prints empty brackets when the attribution is blank. The species picker asked the name service twice for one name (once as you typed, once on blur to check the exact spelling); the blur reads the answer the search already has. The preloaded-font warning was not reproduced here (both faces are used on every page); left as reported. **The plant edit form refused to save while the stored date was in the future** (R2-0, verified): a plant from an older file with a date past today could not have its price edited until the date was fixed; only a date the edit itself typed is judged now. e2e.
15. **The "unreachable reference" browser test could fail on its first try in the full suite** (R1-2). The routes that cut the reference relied on the experimental interception of the service worker's own fetches, which let one through now and then; the test runs without the worker, so the page's own fetches are what the routes see. The full suite once and the test three times over, no retry.

## Checked and not taken

The undo of a removal duplicating a number (R2-0) was not reproduced: the ledger keeps every number ever issued, removed or not, so the next plant takes the next number and Undo brings the removed one back under its own; a unit test now says so across a reload. The `STATUS` literals (R2-0): the routes and the Worker read the one map since round twenty-six, and the formats test compares the page's figures with it; nothing to change. `cutBefore` (R2-0): the cut could be split only by another tab's change stamped in the same millisecond between a notes change and its base; the walk back is a few steps now, by writer, with a test for the interleaved case and for a foreign edit of the same notes between. The "five security lows" were not named in anything that reached this repository and could not be checked; if the reviewer has them, they go in the next round.

**Observability** (R2-7). `wrangler.jsonc` has `"observability": { "enabled": true }`, which keeps the Worker's invocation logs at Cloudflare for a few days: request URLs (which include `/api/names?q=<the name typed>` and the species pages visited) and whatever the Worker prints. That is at odds with "the one thing the server keeps about a visitor is short-lived rate counters" on `/about/how`. The file is the deployer's and is not changed here. Two honest choices: turn it off (`"observability": { "enabled": false }`), which is what the page claims today; or keep it and add a sentence to the privacy section saying the host keeps request logs for N days. The first is recommended for the post; the Worker's own `console.error` lines carry no visitor data either way.

**The Show HN post and licensing** (R2-8). The draft now carries a bracketed sentence to fill: sync is open today, the code has a gate for licensing hosted sync later, and the server is in the repository. What is intended is the author's to say.

## Found by the deploy

16. **The name service answered across every kingdom** (the live check, on the deploy after this round). `/api/names` forwarded to GBIF's suggest with no kingdom filter, and the picker shows the first twelve of what comes back: "gaster" was twelve weevils, fishes and fungi (Gasterosaga, Gasterosteus, Gasterella…) and no Gasteria at all. The live check rotates its genus and prefix by the minute and had not landed on a prefix an animal genus shares until this deploy. The suggest is asked with `higherTaxonKey=6` (Plantae), which for the same prefix gives Gasteria fourth among plants, and the edge cache key is renamed so the day of unfiltered answers already cached is not served. Unit test: the upstream request carries the filter.
