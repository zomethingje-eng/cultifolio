# Review round nine: `ab5a1cc` re-reviewed, triaged

One reviewer re-reviewed the round-eight build against the source and the live site; a second was mid-review and had reached one finding when this pass began. Nothing was a wrong figure. One round-eight change broke a stated rule, three round-eight fixes were incomplete, and the second reviewer's live observation turned out to be the same defect as one of those seen from the other side. All fixed here.

1. **The plants list and the front page sent the grower's species list to the server in a URL** (R9-1; the reviewer's one-thing-to-fix, and a fair one: it was introduced in round eight, item 10, in place of the 3 MB index that existed precisely so the server learns nothing). `/api/entries?slugs=…` is gone. `/api/entries?b=3f,a1` returns the index entries whose slug hashes into those buckets (`src/lib/core/bucket.ts`: FNV-1a, low byte, 256 buckets of about thirty-five species); the device asks by bucket and filters on the device, so the server learns at most which buckets were asked for. The answers are cacheable at the edge and kept by the service worker (network first, cache fallback), so the plants list has its thumbnails and the labels their care lines in the greenhouse, which the old index never gave. Unit test on the bucket function; the offline front-page test now blocks the worker's own fetches too (worker network events are on in `playwright.config.ts`, which is also why that test and the sync tests stopped being flaky: they were seeing the worker fetch through an "offline" context).
2. **A stored key was trusted without checking that the dossier it fetched was the species on the record** (R9-5, and the second reviewer's live observation: a plant renamed to *Copiapoa cinerea* in an earlier round kept its *Echinocereus* key, and its "Habitat versus here" showed Echinocereus's winter nights and summer rain under Copiapoa's name). `dossierForName()` in `src/lib/ui/index.svelte.ts` is now the one resolver for the plant page and the labels: the record's own key first, checked against the record's name (`slug` or `speciesSlug(name.scientific)`), then the species by hash bucket; a wrong or missing key is repaired on the record. The labels memoise dossiers by key (five Astrophytum labels, one request) and no longer fall back to the whole index; neither does the batch page nor a hybrid's parent links.
3. **A removal lost to an edit made while the clock was fast** (R9-2). `stampPast` bumped a change past its own field's stamp only; whether a record is deleted is decided against its latest edit to any field. A `_deleted` change is now stamped past the later of the two. Store test: remove after a fast-clock edit takes, restore takes.
4. **Plants imported from v2 still counted from years ago** (R9-3). The importer stamps changes with the v2 edit times, so the earliest stamp was no better than the acquisition date. The store now records, in `meta`, the day each record arrived in a file (`importedOn`), and `madeOn()` prefers it. Store test, across a reload.
5. **Without JavaScript the letter index looped on the three biggest letters** (R9-4). "More" now carries `?at=<row>`, and the server renders the window from that row; `?from=L` remains for the letter links.
6. **The new worker was not always found until the page asked** (R9-6). `reg.update()` runs after every registration: one conditional GET of the script.
7. **"Over 1 in" is 25.4 mm, and the rule is 25 mm** (R9-7). "over 25 mm (1 in)" in both unit systems.
8. **The late-upload sync test** (baseline): its cross-device waits are now generous where the assertion is exact, and the worker-network setting above removed the cause of its flakiness.

Set aside: serving species photographs on collection pages through the worker (the reviewer's design note, a real point about the image hosts learning which species a device grows from `/plants` and the labels; it is the same disclosure the About page already makes for species pages, and a proxy for third-party images is a larger piece than this pass). The dossier fetches by key are noted in the same spirit: one per species, equivalent to visiting that species' page, and kept by the worker so a page visited once asks no more.
