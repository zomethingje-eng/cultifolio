# Round fifty-nine: three reviews of round fifty-eight

Three reviews of `4598c5f` arrived together: the author's own (`docs/REVIEW-SELF-58.md`, 35 findings from six parallel passes, the serious ones checked again by hand), the "round forty-one" review (R1) and an independent review of the source (R2). The self-review's headline was that round fifty-eight's own account overstated it: several of its claims were false as written, and thirteen of 45 mutations of its fixes were caught by no test. This round takes every finding that held up, in six parts, and states only what a test or a measurement shows. Numbers in brackets are the self-review's.

## 1. The server

1. **One vault could lock everyone out of sync** [1]. "Counted once" was judged on each request's own copy of the vault's meta, so twenty first uploads at once counted one vault twenty times, and about 2,000 held uploads could push the ceiling in all past its limit for good. The "vaults" counter object now records each vault it has counted (`f:<vault id>`) and answers `counted`, `already` or `total` in one step; a vault is admitted before its first write (`admitVault`), and past the ceiling the upload is refused with a 503 (`VaultsClosed`) instead of stored. Test: twenty concurrent first uploads count one.
2. **Rewordings of "a" ranked most of the index** [2]. The short path was chosen from the raw words, so "f a", "var a" and "a a" skipped `short.json`. The path is now chosen from the words the search ranks (`rankedWords`, shared with the search), a query whose exact candidates pass 2,000 is charged as a whole-index pass, and `search`, `searchmiss` and `reference` are counted by the /48 as well. Test: each rewording reads `short.json` and no posting file, with the same answer as the whole index.
3. **Byte totals under concurrency** [9]. Ten DELETEs of one photograph gave its bytes back ten times; the day's first uploads each replaced the day's row with their own listing. A removed object's bytes are now given back once, under its key, etag and upload time (`g:<token>`, swept with the day keys); `take` uses today's row when there is one; uploads not yet written are held as in flight (`p`) and released when they land or fail, so a recount adds them back. Tests in `sync-accounting.test.ts`. The per-address daily cap is still per /64, with no /48 total; that is left for later.
4. **A rejected manifest fell through to the bare index** [10]. It now keeps the corpus held before, remembers the rejected manifest's etag so it is not re-read every minute, and refuses a manifest whose species count differs from its index. `short.json`'s entries are validated before use. Test: `manifest-refused.test.ts`.
5. **The prune** [11]. `rclone delete` gets `--use-server-modtime`, so `--min-age 24h` reads the upload date, not the local file's; `--keep-list` also keeps what the local `manifest.json` and `manifest.prev.json` name; DEPLOY.md section 5 re-reads the live manifest before the delete.
6. **The origin check on an encoded path** [13]. `/api/%73ync/vault` from another site passed the hook. The hook now refuses every cross-site write on any path (the site has none a stranger may make), the method read safely. Tests: encoded paths, and `handle` itself refusing before any route runs.
7. **One corpus per request, all the way down** [24]. The hook loads the corpus once into `event.locals.corpus`; the page cache's key, the home page's rows and the species page's load all read it, where each loaded its own and a refresh between them could store one corpus's page under the other's id. Test: `page-corpus.test.ts`.
8. **Smaller server items** [24, 34]. `readBody` allocates on the first chunk, not before a byte arrives. Two creations of one vault at once: the meta is written with `onlyIf`, so only one answers `created`. A row's species list is kept per index rather than slugified on every render. `/api/dossier` is public only when asked under the current corpus id. The service worker keeps only query-less navigations, so `/?open=aloe` offline is never another page's copy. The sync engine's requests have timeouts (30 s; 180 s for a photograph, 120 s for a batch).
9. **Photographs from a host nobody was told about** (R2). A photograph that reached GBIF from another dataset kept that dataset's own address, and a species page whose lead photograph was one fetched it from there. The page now loads it from GBIF's image cache (`shownAt`), so the three hosts `/about/how` names are the only ones. Test.
10. **A 404 that said "not a synonym" when it had not asked** (rule 2). When GBIF's name service does not answer, the species 404 now says the older-name check was not made, and is not cached. Test.

## 2. The collection on the device

1. **Held changes and the device's own clock** (R1, R2). A device whose clock had never been checked against the server could park its own changes or hold a peer's on a reading it had no reason to trust. Changes are now held or parked only once the clock has been confirmed by the sync server (`clockChecked()`); a device whose clock reads earlier than its own last change says so under the top bar and acts on nothing. FOLD_RULES is 4, so every device folds its log once on the first load.
2. **No repair written without the grower** (R1, R2; rule 5). A sync run, a restore and a pull no longer renumber anything on their own; two records under one number are shown with the button, and only the button writes. A restored record yields its old number to the record that has held it since, and the page says which number it got [32]. The notice says "recorded first", not "created earlier", since a minute of clock skew can reverse creation order.
3. **"Notes replaced" listed text that was not replaced** [20]. The reading now skips held and parked edits and pairs each edit with its base by the same writer, in one pass (it was quadratic [34]). The species notes on the plant page are a reading too [33]: the species page's own save writes `myNotesBase`, the species page shows what an edit replaced, and the line the plant page wrote into a plant's events is gone. Tests: `notes-replaced.test.ts`.
4. **The lock** [19, 23]. A tab that finds another tab running retries in five seconds instead of waiting for the next focus. The lock's reload of the sync record replaces it whole and refreshes the page's own copies; held stamps are saved where they are added, so the reload no longer loses them.
5. **The fold-rules guard** [22]. It now hashes the whole of `vault.ts` and the collection's `load`, `rebuild` and `catchUp`, and the snapshot heartbeat (`touchFold`). A snapshot dated in the future is not kept.
6. **Values inside `measures`** [34] must be finite numbers; the refusal names the field and the record ("floorC of a location must be a finite number").

## 4. The interface and accessibility

The interface pass was made in a copy by a separate agent against the self-review's list, measured there in a phone emulation and its end-to-end run, and reviewed here before it was merged. What has a test in the suite says so; the rest was measured in that pass and is not guarded by a test.

1. **Focus under the bars** [14]. A focus handler scrolls the focused element clear of whatever is drawn at the top and bottom edges, since `scroll-margin` acts only when the browser scrolls, and brings a sideways-scrolling row round to a chip first. Test: at 390, thirty Tabs forward and back through `/about/how` and forty back up the species page find no focused control covered at its centre; with the handler removed, the test fails.
2. **Field edges at 3:1** [15]. One rule gives inputs, selects and text areas `--field-edge` at an id's weight, so the pages' own rules no longer win; selects and text areas measured 1.28:1 and 1.59:1 before, and the token is 3.0 to 3.6:1 in light and 4.6 to 5.2:1 in dark.
3. **Sizes and tap targets** [30]. Nothing under 11 px in the charts; the toast's Undo, the list's Water, the species page's card actions, the sort menu and the reference-photo offer take the 44 px tap token under a finger; links in text are underlined in both themes; the primary button's hover keeps 4.5:1.
4. **The place page** [21, 26]. A figure it cannot store is refused with a sentence under its field, never written as empty (test); the watering rhythm takes the plant form's rule; the empty-state line no longer sits over a Watering card; an altitude saved without coordinates has its own row; the due count shows before a first watering.
5. **Separators and truncation** [35]: a place's name and kind, and "Greenhouse · 0 plants", are separated by a box with its own margins, not by spaces a flex row drops; the list head's count wraps instead of being cut; the skip link is the first Tab on a private page loaded directly; nothing scrolls sideways at 200% text on `/about/formats`, `/propagation` or compare's picker.
6. **The lightbox** says the photograph's place in the set, and announces a change of photograph.

## 5. The harness

1. **The sync stand-in returns copies** [17], as IndexedDB does; that exposed the held-stamp loss in 2.4, now fixed, and a crash on an old stored record without defaults (`withDefaults`).
2. **Mutations** [18]. Tests now catch each of the self-review's list: the hook's call to `_foreignWrite`, the `short.json` path, the notice against the keeper in id order, a restore that repairs, a load that writes (`rule5.test.ts` takes its baseline before the reload, and compares the whole log, not its length), the backup's parked set through a real merge (`backup-parked.test.ts`), the photograph's body read before its proof, the decoded page-cache key, and an atomic `updateMeta` over fake-indexeddb. The proof, the decoded key and the parked set were checked here by reverting the fix, and each test fails; the others are the self-review's proposed tests, each of which it checked the same way.
3. **What one test left for the next** [31]. The sync tests' server keeps its KV across a device's reboot, so "full vault" is now asserted after the reload; engines booted earlier have their timers cleared; the gate that could switch two held-change assertions off silently is an assertion. The BroadcastChannels a test opened are closed when it ends, and the whole meta store is cleared between tests (`tests/unit/helpers/isolate.ts`). The lock tests wait on the push reaching the server, not 50 ms. The search generator's "wider" case has 90 s; the backup's 3-second bound, which timed its own fixture, is gone.
4. **R2's Windows run.** The share-card test waited for a download that Chromium on Windows sends to the system share sheet; it now tests the download with no share, and the share path with a recording stand-in. The settings failure could not be reproduced here; the likeliest cause is typing before the page hydrated on a slow machine, which drops the value and leaves Save with no handler, so the layout now marks the document when it has hydrated and every settings test waits for it. The author's Windows run after the deploy passed both, and 99 of 102 in all. The other three were one cause and a cold start. Three tests left the page while a save was still being written (a batch edit then a reload, a place's dry month then Today, a note then a sync); a navigation cancels the write, so on a slower machine the save was lost and the next assertion failed. Each now waits for its form to close, which happens only when the write has landed. The first test of a run timed out on the server's first render; one request before the tests now takes that cost with its own allowance. All four pass here.
