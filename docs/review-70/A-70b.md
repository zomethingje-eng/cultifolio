# Round seventy-b, agent A: summaries after the owner's corpus step

Commit `850d649` on `r70b`. The files changed are `summary-proof.ts`, `summary-fill.ts` and `sources/wikipedia.ts`. The tests are `tests/unit/r70ab-summaries.test.ts` (new) and the helper `r70a-summary-world.ts`, which now answers GBIF's `species/match` and Kew's rows.

## 1. The four summaries the rebuild lost

**Why they failed.**

- **Erythrina caffra and Rhododendron kanehirae** were refused by A2. Round seventy refused any binomial in one of the species' genera that was not its name or an older name. That covered "Erythrina afra" (the item's own sitelink) and "Rhododendron kanehirai" (the same).
- **Sprekelia formosissima** failed for a different reason. Wikipedia's article "Zephyranthes formosissima" is sitelinked to Wikidata's *genus* item (Q159042, P105 genus, P225 Sprekelia). Wikidata does have a species item called Zephyranthes formosissima (Q133098246), but it states no basionym. So none of the round-seventy proofs could reach it, and Kew's count for the genus Sprekelia is 0 because Kew sinks the genus.

**A2 is narrowed as asked.** A binomial that is neither the name nor an older name is now asked of GBIF's backbone. This is one `species/match?strict=true&kingdom=Plantae` request, the same URL B's `heldAtGbifElsewhere` uses.

- **Refused** when GBIF holds the binomial as another species, or under a variety or subspecies of this one. The second case covers Drosera tomentosa, which GBIF holds under Drosera montana var. tomentosa. An autonym counts as the species itself: GBIF holds Huernia zebrina under Ceropegia zebrina subsp. zebrina, which costs one more request to read.
- **Not refused** when GBIF does not hold the binomial at all ("Erythrina afra", "Zephyranthes formosissima"). Two-word common names ("Venus flytrap") fall here too.
- **Taken as `older-name`** when GBIF holds the binomial as this species: "a name GBIF holds as a synonym of this species".

No reference lookup was needed. Every species of the reference is an accepted GBIF species, so "another species of this reference" is already caught by the GBIF answer.

**A new same-type proof read from Kew's names.** It applies when Kew's WCVP (through GBIF) holds this species' name, in every row it has, as a synonym of the title, with the same epithet by `spellingKey` and the same bracketed basionym author. Example: "Kew's WCVP holds Sprekelia formosissima (L.) Herb. under Zephyranthes formosissima (L.) Z.H.Feng, both from a basionym by L."

A Kew synonym from another basionym is a lump and proves nothing. Agave vivipara shows the second guard: Kew holds two rows under that name, Arruda's (a synonym) and Linnaeus's (accepted), so it proves nothing. Both guards are tested.

**Results on real data (2026-10-13):**

- **Erythrina caffra:** ok, as "the English article of this species' Wikidata item (Q1955238)". After C's need it needs no proof at all.
- **Sprekelia formosissima:** ok, by Kew's names.
- **Rhododendron kanehirae:** still none. GBIF holds R. kanehirai (5733624) and R. kanehirae (4936864) as two accepted species, so by the narrowed rule it is another species. It stands once C applies the spelling need below. The test is written that way and fails until then.
- **Matteuccia struthiopteris:** none, and correctly so. Kew holds the genus Matteuccia as a synonym (M. struthiopteris is Onoclea struthiopteris at Kew), so there is no accepted genus and no count. GBIF's backbone counts 2. No other proof applies.

## 2. `--fill summaries`: 234 not checked

**The cause.** `speciesItems` returned an error for all candidates as soon as one batch of fifty failed, so every species with an item was counted not checked. Wikidata was lagged that session (the next `--fill wikidata` stopped on "Waiting for wdqs1016: 7.6 seconds lagged").

**The 88 were read.** The 88 carried the record "whose lead is this species'", which sends them to the online pass. Only Ariocarpus, settled offline by name, changed. So the 88 were among the 234.

**What happens now:**

- A failed batch leaves only its own fifty unanswered.
- Each call already waits as the builder's do: `mwGet` asks up to five times on maxlag, because `startCorpusRun` sets `mwWait.tries` at the script's start, and the fetch layer retries 429.
- On top of that, everything a source did not answer is asked again after ten minutes, twice (`fillRounds`). Ten minutes is the fetch layer's cooling time. Only after the second retry is a summary counted not checked.
- Only a corpus run waits; tests and single calls do not.

Tested: one lagged pass is followed by a wait and the proof. Of 51 species, one failed batch leaves 50 unchecked, not 51.

## 3. `spellingKey`: a need for C (`src/lib/dossier/epithet.ts`)

Add the following before the `ae`/`oe` line (the diff is at `review-70/A-70b-epithet-need.diff`):

```ts
  // Round seventy-b (agent A's need): a genitive of a name ending in -a, written -ai after a consonant (kanehirai,
  // shimadai), is the -ae the Code asks for (Rec. 60C.1); and "caffr-" is the "afr-" the 2024 Madrid congress put in its
  // place (Erythrina caffra, afra). Neither joins two accepted species of the reference.
  e = e.replace(/^caffr/, 'afr').replace(/([^aeiouyh])ai$/, '$1ae');
```

**What it merges.** I grouped the reference's 8,947 accepted names by genus and key before and after the change. It joins no new pair. The two pairs that share a key were there before it:

- Ceropegia ciliatior and Ceropegia ciliatioris. This is a pre-existing merge of two accepted species by the current rule, because "-is" is stripped. It is C's to look at.
- A double "Conophytum calculus" entry.

**What it touches.** The epithets in -ai after a consonant (arechavaletai, aspillagai, garaventai, herrerai, hodai, lujai, nicolai, shimadai, somai) and caffra and caffrum. Bihai, thai, ahuai and ahouai are left alone because a vowel or "h" precedes the -ai.

**Tests.** The case in `r70ab-summaries.test.ts` fails until the need is applied. With it applied, the full suite has two failures. One is my own old guard, which I have since fixed: it used Kew's real "Harpephyllum afrum", which correctly becomes this species. The other is P's seam test (below).
