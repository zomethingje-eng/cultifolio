# Review round eight: two outside re-reviews of `13d81aa`, triaged

The two reviewers from round seven each re-reviewed the deployed build with the same brief, checking every round-seven item against the source and the live site. The first returned 5 findings, the second 14. Every one was checked against the source. Merged and in the order they were fixed. "R-A n" is the first review's numbering, "R-B n" the second's.

## Not code: the deployment

1. **Every HTML response carried Cloudflare's Web Analytics beacon** (R-B 1). Cloudflare's "automatic setup" injects `static.cloudflareinsights.com/beacon.min.js` at the edge, before `</body>`, on any request that accepts HTML. The Content Security Policy added in round seven blocks it from running (and logs two console errors per page), but it was served, and before round seven it ran, under a site that says "no analytics". This is a dashboard setting, not code: it is turned off in Web Analytics for the zone, `docs/DEPLOY.md` now has the setting and the outside check (`curl -sH 'accept: text/html' https://cultifolio.com/ | grep -c cloudflareinsights` must print 0), and the deploy walk includes it. Whether and how to say on `/about/how` that the beacon was present for a period is the author's call; the reviewer's suggestion is to say how long.

## Data integrity

2. **Two tabs of one browser stamping the same millisecond gave two plants one identity** (R-A 1, the reviewer's critical). Round seven made number allocation transactional, but both tabs used one device id and each had its own clock; at the same millisecond both minted the same record id and the same change keys, and the second write overwrote the first. Fixed in `src/lib/db/collection.svelte.ts`: each tab is its own writer, the device id plus a four-character tag (within the HLC's sixteen), while the device alone still names the machine to sync and to the hold rule, which now matches the writer by that prefix (`isHeld`, `ownStamp`). e2e: "two tabs whose clocks read the same millisecond still make two plants", with both page clocks fixed at one instant.
3. **Following this device's own future stamps poisoned every later edit for other devices** (R-B 4). Round seven's clock fix meant that after one edit made while the clock was a year fast, the clock kept stamping a year ahead after the correction, and every other device held everything this one wrote until then. Reverted in `src/lib/core/hlc.ts`: the clock never follows a stamp far ahead, its own included. The case round seven was fixing (an edit after the correction losing to the fast-stamped value) is handled per field instead: a local change to a field whose current stamp is ahead of the clock is stamped just past that stamp (`hlcAfter`, `Collection.stampPast`), so the edit wins the field and nothing else moves. Store test: the field is won, other fields and records carry real time.
4. **The duplicate-number repair depended on the device's own ledger, so two devices could repair one duplicate to two different numbers** (R-B 5). The repair now derives its free number from the log alone (`takenNumbers(kind, false)`), as every device must derive the same repair from the same merged log.
5. **A saved southern site rendered northern months first, and permanently without JavaScript** (R-A 2; open since round six). The site lives in local storage, which the server cannot see. Fixed: saving a site sets a `cultifolio.hemi` cookie (`n`/`s`, nothing else), which the species and compare pages read on the server to seed the reader's hemisphere until the site store loads.
6. **Subspecies and varieties were joined to their species on the plant page only** (R-B 7). `speciesSlug()` in `src/lib/core/names.ts` is now the one join, used by the species page's "yours", the front page's own tiles, the plants list's thumbnails, the labels' care lines, the batch page, and the taxon records the add and sow forms create (which now carry the species name).
7. **Every cross-tab write re-read and re-folded the whole log** (R-A 4, R-B 6). `catchUp()` filtered by the wrong key. The store keeps a set of applied HLCs and folds only what it has not seen.

## Flows

8. **The service-worker take-over never fired for the case that matters** (R-B 2). It waited for the version poll, which only a page already open at deploy time sees; a returning visitor's first page loaded under the old worker and the new one waited forever. Fixed in `src/routes/+layout.svelte`: a waiting worker is told to take over on every load, and on `updatefound` once installed; the poll path stays for a page open across a deploy. Doing that exposed the reason the reviewers kept finding a worker in `waiting`: SvelteKit registers `service-worker.js` itself with an inline script, and the layout registered it again, and the second registration during the first's install always produced a spurious second worker, which sat waiting forever before and, with the take-over, reloaded the page without end. `kit.serviceWorker.register` is now `false`; the layout's registration is the only one. **The reload that followed threw away unsaved work** (R-B 3): it now happens at once only in the first four seconds of a page, and otherwise at the next navigation (`beforeNavigate`, a full load of the destination), never mid-form.
9. **Our own forecast refusals were worded as the source not answering, and the new limit counted cache hits** (R-B 8). `forecastRefusal()` in `src/lib/weather/client.ts` words a 429 as this site asking the device to wait and a 400 as this place's altitude or coordinates being out of range; the source is blamed only for a failure of the source. The rate limit is checked after the edge-cache lookup, so a hit costs nothing. The bench form refuses an altitude outside −500 to 9000 m with the likely reason (feet).
10. **The plants list, the labels and the front page still fetched the 3 MB index** (R-B 9). A small endpoint, `/api/entries?slugs=`, returns the entries for a grower's own species; the plants list takes its thumbnails from it, the front page its own tiles, and the labels ask for each plant's dossier by its own key (the file the offline worker keeps), with the index as the fallback for a plant without one. The whole index is fetched only for a search or a chip.
11. **With JavaScript off, and for crawlers, the catalogue stopped at letter A** (R-B 10). The letter links now carry `?from=L`, which the server renders a window from, so a reader without JavaScript follows the index by full navigations; with JavaScript the index still jumps in place. `/sitemap.xml` lists every species page and every genus row, and `/robots.txt` points at it.
12. **"Water overdue" asserted a schedule the app does not have** (R-A 3). The chip reads "Not watered 21+ days", with a title saying it is a fact about the record; the row wording was already factual. **On a phone the list hid that figure** (R-B 13): it is now a second line under the name.
13. **Plants imported from v2 were overdue and "not seen" on day one** (R-B 12). Their ids carry no time. The store now remembers each record's earliest stamp (`born`), and `collection.madeOn()` falls back to it, so an import counts from the day it was imported.
14. **A new place went inside the picked place** was fixed in round seven; the reviewer confirms.

## Confusing and cosmetic

15. **The first card stated a figure the page flagged as indicative three screens down** (R-B 11). A line under the glance row now says "Under a dozen records behind these figures (N): treat them as indicative" whenever the climate rests on fewer than twelve.
16. **"40 °F would cook seed"; "12 months over 0.98 in"** (R-B 14). Too cold has its own sentence; the threshold reads "over 1 in" or "over 25 mm".
17. **The plant-page skeleton was in the wrong order and increased the shift** (R-A 5). The pre-vault DOM now follows the loaded order: hero placeholder, then an id card with the number as its title and blank actions, then the verb bar's height; the two main fonts are preloaded.
