# Review round thirty-eight: two reviews of the deployed `6c06b1f`, triaged, and a pass of my own

The first reviewer's round thirty-three (eleven findings, with an independent review of the sync path and five wording notes) and the second reviewer's round twenty-five (five findings, with fresh Lighthouse runs). Both reviewed what rounds thirty-six and thirty-seven deployed. Every finding was checked in the source or reproduced. "R1-n" is the first reviewer's; "R2-n" the second's. Each reviewer's one thing to fix was a different thing, and both were right: a repair button that could overwrite a real status on every device, and a duplicate number carried across every reload.

## The collection

1. **A duplicate number already in the log was never repaired** (R2-1, the reviewer's one thing to fix; reproduced). A merge and a pull run the deterministic repair; a load did not, so two whole plants under `2026-0013` from before the ledger were carried across every reload, `accession()` answered the first for good, and the backup faithfully kept both. `load()` runs the same repair after the fold and before `ready`. The test writes two whole records under one number, resets the module as a fresh tab would, loads, and finds the later-created one renumbered with its note; it fails without the load-time call.
2. **"Mark it as growing" could overwrite the real status everywhere** (R1-1, the reviewer's one thing to fix; read). The button sat under a sentence saying a set-aside batch may still hold the status, and a change stamped now is newer than that batch's, so last-writer-wins would keep "growing" on every device once it synced, over a "sold" the newer device had right. The button is offered only while nothing is set aside on Sync (a set-aside photograph holds no field, so it does not count), and the sentence then says a set-aside batch may hold the value and this build will read it when it can.
3. **Waiting records of the oldest shape, and waiting batches and places** (R1-3, reproduced). `waitingAccession` matched `acc` only, so a plant whose number is its id still read "given to a plant since removed"; a waiting batch read "No batch with this number"; a waiting place "No location with that id". One `waiting(kind, idOrNo)` goes by `accNo`/`sowNo` or the id, and one `WaitingRecord` component says the same thing on all three pages, naming the field (name, status, method, date, count). The restore preview names a plant by `accNo` and a batch by `sowNo`, as their pages address them.
4. **A label printed a mean night as the night when the status was `none`** (R1-2, reproduced). The label's rule covered refused, skipped and sea, not none or a missing status. Without a daily extremes series there is no night to print, whatever the reason: `nightUnchecked` is `!extremes`, the labels page counts every such label, and its line says why. Tests for `none` and for no status at all.
5. **A deflated photograph entry could cost a hundred seconds** (R1-11, low). Every writer has stored the photographs as they are (round twenty-eight's note says so), so a deflated photograph entry is not ours, and inflating one is the one cost the declared size does not bound. Refused at the table of contents. The tests' hand-made zips store their photographs now, and the old "six deflated photographs add up past the file" case is refused earlier, as the first deflated one.

## The sync path

6. **The creation route read a body of any size before any check** (R1-4, reproduced by the reviewer with a 64 MB probe). `request.json()` ran after the rate limit and before the token was checked, so round thirty-six's premise ("the routes authenticate before they read") was false for the one route that has no token to check. It reads through the capped reader at a kilobyte (a creation body is under two hundred bytes) and parses what it got; a stranger's chunked flood is a 413 after a few chunks. Test through the route.
7. **A listing could park the cursor in the future** (R1-5, read). The cursor took the greatest arrival time in a listing, so one far-future arrival (a server clock, or a listing shaped by whoever holds the token) made every later `since=` empty for good, silently. An arrival more than ten minutes past this clock leaves the cursor where it was (the batch itself is still read; `have` keeps it from folding twice) and the sync page says so in its own line, not as a refusal from this device. Test: a batch dated a day ahead, the cursor unmoved, a later batch still arriving.
8. **A batch's name was not in its seal** (R1-7, reproduced). Round thirty-six's note said the AAD binds a batch's name; photographs were bound to their id, batches were not, so a batch fetched with the token could be posted again under a fresh name and opened there. `sealJson` and `openJson` take the name; a batch is sealed under its name and opened under it, and one sealed before (every batch now on the server) opens under the unnamed data as a photograph from before its binding does. The formats page says so, and its test seals a batch under a name and opens it by the page's own description.
9. **A /48 could spend the day's shared ceiling** (R1-8). Addresses are keyed by /64, and a /48 holds 65,536 of them, so forty /64s could take the two hundred a day. The counters object counts a /48 as well, at four times one address's allowance, refunded and swept with it; IPv4 carries no network key. The KV fallback path (tests, a dev server without the object) stays as it was: bounding, not accounting.
10. **The token comment, and what /about/how says** (R1-6). The server comment said the token travelled once; it travels as the bearer of every request, so it is visible wherever request headers are, and a holder of it can read ciphertext, fill the vault to its limit and take a photograph's name first, but open nothing. /about/how says that now, and the rest the reviewer asked for: the key sits in the browser's storage in the clear, there is no rotation or revocation ("Stop syncing" forgets the key here and revokes nothing), an exposed key means a new vault, and a withheld batch is not something a device can detect, since batches carry no chain. A key-holder-only overwrite of a server object this device cannot open is noted as the design for a round that can change the wire; not taken now.

## The pages

11. **A quick 5xx, or a portal's 200, beat the held copy** (R1-9, reproduced). Round thirty-six's race returned whatever came first. Only an answer worth keeping wins it; otherwise the held copy answers and the fetch finishes in the background.
12. **The background refresh did not wait for its cache write** (R2-2). `cache.put` was started with `void`, so the promise handed to `waitUntil` settled at the fetch and the write could be cut off with the event. Every cache write in the worker is a promise handed to `waitUntil` now.
13. **A monotypic genus quoted its paragraph twice** (R2-3, Welwitschia). When the genus excerpt is the species excerpt or a prefix of it (or the reverse), spacing and case aside, the genus block is not shown: a rule over two quoted strings. A genus fixture carries the species article, and an e2e test holds both cases.
14. **A misspelling with a trailing marker found nothing** (R1-10, reproduced). The near match runs without the marker too. Test.
15. **Wording** (R1). Compare's row is headed "Coldest night (a floor where one is read)"; /about/how's floor paragraph says no floor is read without extremes and names the figure shown instead; the sheet's method line says the same instead of "the cold floor is the figure named in its sentence"; where the type table raises the floor over a mean night, the short line and the share card say "coldest mean night", keeping "habitat night" for a night reading; the plants page has its space back ("does not have (a file…").

## Not taken, with reasons

**The mobile species page's render delay** (R2-5): the two changes proposed (fallback font metric overrides, `content-visibility` on the lower sections) are tuning that has to be measured in a trace, and this sandbox cannot run Lighthouse against the site; the font overrides need Newsreader's own metrics to be right. Deferred with the instructions as given. **A worker test with a delayed `cache.put`** (R2-2): there is no service-worker harness in the suite; the change is read, not tested. **The Show HN draft** (R2-4): the author's. **Nine Aloes** (R1): counted over the index on the PC after the deploy, and it is nine. The list was derived (every WCVP-accepted species of 172 collector genera, plus the 2,500 species most recorded as cultivated on iNaturalist), and the derivation deliberately leaves the very large genera, Aloe among them, to the cultivated count alone. /about/how now says what the list is built from and names the genera it does not take whole, in a follow-up commit to this round; taking Aloe whole is a corpus decision for the author (about six hundred species to build with the network sources), noted, not made here.
