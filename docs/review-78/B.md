**2. Batched sources.**

- `src/lib/dossier/batch.ts`: before each chunk of 500 species, one SPARQL query for the items of 200 GBIF keys (statements of every rank, `p:P846/ps:P846`, as `haswbstatement` counts a deprecated one: Q651038, key 1761), one `wbgetentities` of 50 items, one TextExtracts read of 20 leads. Each answer is held under the exact address the builder asks for one species (the P846 search, the item read, the REST summary), so `crossIds`, `summary` and the title proof run unchanged. Anything not held goes through as before. A species listed by name has its GBIF name match asked by the batch and held for the builder (asked once either way), so it is batched too. Wired in `scripts/build-dossiers.ts`; `--no-batch` turns it off; a re-derivation does not use it.
- **Rule 2:** a batch that fails is held as that failure for each of its species (refused or error, with "batched: …" in the record), so each is not checked and keeps the previous build's section; a title Wikipedia lacks is `none` only because the batch said `missing`, as its 404 did. An answer TextExtracts cuts short holds only the pages that came whole.
- **Rule 3:** nothing is matched in the batch; the item is taken only when one item carries the key, as before.
- **Rule 4:** the summary keeps CC BY-SA 4.0 and the article's address, which the page links and credits.
- **Wikimedia pacing** (`fetch.ts`, `paceKey`): Wikipedia, Wikidata and Commons are one pace, 0.35 s (171 a minute), under Wikimedia's 2026 allowance of 200 a minute for a named client across all its sites; `query.wikidata.org` 1.1 s. Each host was paced alone at 0.25 s before, together up to 720 a minute.
- **Kew's names from Kew's file** (`src/lib/dossier/kew-rows.ts`, `scripts/kew-rows-load.ts`): with `--bulk`, GBIF's copy of Kew's checklist (`/species?datasetKey=<WCVP>&name=`, asked by `kewIpni`, `kewName`, `crossIds`, the summary proof, `inat.ts` and `photo-kind.ts`) is answered from `wcvp_names.csv` in GBIF's shape: GBIF's status mapping (measured: Accepted, Local Biotype, Artificial Hybrid → ACCEPTED; Synonym, Invalid, Illegitimate, Orthographic → SYNONYM; Unplaced → DOUBTFUL; Misapplied → MISAPPLIED), a synonym's family its accepted entry's (as GBIF writes it, which `kewIpni`'s family rule reads), the POWO address of `powo_id`. Its keys are `10^10 + plant_name_id`, answered for the two requests that read a key back, stored nowhere. Names of genera not loaded, and names of three words, go to GBIF. `--kew-api` turns it off.
- **Common names: not replaced.** GBIF's API is not the backbone archive: see Measured.

**3. iNaturalist.**

- `src/lib/dossier/day-budget.ts`: every run of a UTC day together asks `api.inaturalist.org` at most 9,000 times (`--inat-budget <n>`), counted in `cache/day-budget/` (droppable), then answers "refused: today's allowance … spent; asked again tomorrow". `--fill inat` writes each dossier as it goes and stops with exit 3 and "run this again tomorrow (UTC), and it goes on from here", which `corpus-step.mjs` reads as unfinished, so it runs over days. `--fill inat --cultivated` asks the cultivated set alone.
- **Cultivated photographs by the owner's rule of 2026-10-19** (`sources/inat.ts`: `cultivatedUrl`, `agreedCaptive`, `CULTIVATED_RULE`, `cultivatedSettled`). Request: `/v1/observations?taxon_id=<id>&photo_license=cc0,cc-by,cc-by-sa&photos=true&captive=true&identifications=most_agree&order_by=votes&per_page=12`. No `quality_grade`: iNaturalist makes every captive observation casual (its help article 151000169936: a verifiable observation "isn't of a captive or cultivated organism"), which is why the old `quality_grade=research&captive=true` found nothing. Each filter is as iNaturalist's API documents it (https://api.inaturalist.org/v1/docs/, `swagger.json`: `captive` "Captive or cultivated observations", `taxon_id` "… and their descendants", `photo_license` "Must have at least one photo with this license", `identifications` "Identifications must meet these criteria", `most_agree`). Then each observation is taken only when `captive` is true, at least two of `identifications[]` are `current`, `community_taxon_id` equals `taxon.id`, `num_identification_disagreements` is 0, and every current identification's taxon is in `taxon.ancestor_ids` (the taxon or above it) or has the taxon in its own `ancestor_ids` (below it). Each photograph's own licence and author are checked as before (rule 4). A descendant taxon is read as for the wild set (`observedAsAnother`, Kew's `placedElsewhere`; `inat-kew-fill.ts`, as `--fill inat --bulk` does). A failed request stays refused or error, not checked (rule 2); "none" only when iNaturalist answered and no observation agrees. The record now names the rule, so `--fill inat` asks again every record of the rule before (`cultivatedSettled`); still budgeted at 9,000 a day and resumable. **The page** already marks a captive photograph "cultivated" on its thumbnail and "in cultivation" in its title, label and the lead's credit (`Photos.svelte`, `species/[slug]/+page.svelte`); unchanged, and tested.
