# Review round thirteen: two reviews of `31b83f1`, triaged

Both reviewers came back on the round-twelve build. The first (with two further readers, as in round twelve) found twelve things, one of them a fault in round twelve's own fix; the second found a race on the bench page and a weakness in the sync tests, and verified round twelve's three privacy and cost findings closed on the live site. Every finding was checked in the source and is real; all fourteen are done here. "A-n" is the first review's numbering, "B-n" the second's. Both reviewers' e2e runs were red in places mine were green; the causes turned out to be two test defects (B-2 and the labels count) and are fixed as tests, with the product defect B-1 that one of them was hiding fixed as a product defect.

## Data lost or wrong

1. **A batch set aside by an earlier build was dropped from the quarantine and never fetched** (A-1; the first reviewer's data-loss finding). Round twelve's retry removed the entry and relied on the next listing, which starts a minute before the cursor and could never reach a batch that arrived days ago; the "N batches could not be read" count fell to zero and the changes were gone without a trace. Fixed in `src/lib/sync/engine.svelte.ts`: a batch set aside by another build is fetched by key (`takeBatch`, the same path the listing uses), folded, and leaves the quarantine only once it has; a failure to read it again is noted afresh by this build. Engine test: a good batch marked as set aside by an older build, with the cursor a day past its arrival, is fetched by key, the record appears, and the quarantine is empty.
2. **Two commits could still collide on one stamp** (A-7). Round twelve's `given` set covered one commit; two commits each bumping a different field past this device's own fast stamps (two tabs, one wall and count) landed on one stamp, and the strict `add` then refused the second write, on every retry. `stampPast` now also steps past any stamp already in the fold (`applied`), and the duplicate-number repair does not mint a stamp already in the log (a repair held for being ahead of the clock was re-minted and refused on every pull). Store test with two tab-writers' stamps three months ahead: both commits land, both values survive a reload; fails against the old line.
3. **A removal under a repeated stamp went to whichever copy arrived first** (A-8). `apply()` now breaks that tie the way it breaks a value tie: "removed" wins, in any order. Fold test.
4. **The v2 importer gave the same change different stamps on different builds** (A-5). Round twelve inserted the number field first, so every field after it moved one counter up; the same file imported on two builds disagreed on which stamp a field carried. The number is now the last field on a plant or batch, so the fields before it keep the stamps earlier builds gave them, and a tombstone's number is stamped one millisecond before the removal under its own writer tag, so the removal keeps its stamp and stays a removal. Import test: the removal's stamp is byte-for-byte what the round-eleven build wrote.

## What leaves the device

5. **Hovering a species link on a private page sent the species' name to the server** (A-2; the first reviewer's one thing to fix). `data-sveltekit-preload-data="hover"` on `<body>` preloaded `/species/<slug>/__data.json` from the plant page's "Species page" link, from the plants list, the labels, the batch page and the front page's own tiles, before any click. The layout now sets preloading off on `<main>` for the private routes (`/plants`, `/sowings`, `/benches`, `/labels`, `/backup`, `/sync`, `/settings`, `/frost`), and the front page sets it off on the own tiles, the Today card and the plants-found list; the public catalogue still preloads, since a visitor's browsing is not the collection. e2e: hovering the plant page's link and an own tile sends no `__data.json`; hovering a catalogue tile does.
6. **"The one thing the server sees" was not the one thing** (A-3). The frost watch sends the site's and each place's coordinates, the picker sends the typed name, and a click through to a species page names the species. `/about/how`, the README and the Show HN draft now give the list in full and say it is the whole list: the hash bucket of each species grown, the coordinates for the frost watch (rounded to a hundredth of a degree on the server before the weather services see them), the typed name in the picker, and the species page clicked through to; nothing on hover; no third-party host unless the photographs are switched on.

## Wrong on screen

7. **Editing a place could leave a forecast saying "All clear" for the old coordinates** (B-1; the second reviewer's one thing to fix). `save()` cleared the forecast and the effect fetched the new one, but an answer for the old coordinates that landed afterwards filled the slot and the effect's guard then kept the new answer out. Every forecast is now keyed to the conditions it was asked for (coordinates, altitude, units); an answer whose key is no longer the place's is dropped. e2e: the old point's answer is delayed past the edit and the new point's warning stays on screen.
8. **Labels printed an unreachable reference as if the species had no figures** (A-6). A failed request, a 429 and "not in the reference" all became an empty care line. `sheetForName` already distinguishes them; the labels page now does too: a label whose sheet was not reached says "care line not checked: the reference was not reached", the page says how many and offers "Try again", and the Print button waits while sheets are still being read. e2e with the sheet route answering 429, then released.
9. **The bench frost watch missed a night that reached the floor exactly** (A-11). `<=`, and the sentence says "reaches this place's floor". e2e.
10. **The skip-cells input and the plant count took fractions and blanks literally** (A-10). A cleared skip box skipped one cell (`Array(null)`), 2.5 threw and stopped the preview, 99 on a 30-cell sheet printed three blank pages; a count of 2.5 made three plants. Both go through `numberOrNull`, floored and clamped (skip to the sheet, count to 1–200), and the add form says how many will be added when the figure was changed. e2e for the skip box.

## Cost, staleness and scale

11. **The sheets route accepted any corpus id, so a stale bucket could be cached under the new one** (A-4). The isolate cache was keyed by bucket alone, and a request under a made-up `c` was stored at the edge under it. The route now reads the current corpus id itself: the isolate cache is keyed by corpus and bucket, a request under the current id is cached at the edge under it, and a request under any other id (a device that has not asked `/api/corpus` since a refresh) is answered `no-store` and never put. Route tests for both.
12. **The sheets rate limit was charged per request, not per bucket derived** (A-12). Now per bucket; the limit is 200 derived buckets per address per ten minutes (a bucket is one object read since round twelve). Route test: fifty requests of four each, then a refusal, and a cached bucket not charged.
13. **`have` never shrank on a device that synced before round twelve** (A-9). Keys with no recorded arrival were kept forever. They are now dropped like the others: a listing can only show them again inside the overlap, where a batch folded twice is harmless.

## The test suite

14. **The sync tests could read the "Synced" that was already on screen** (B-2). The engine counts finished runs and the sync page's status card carries the count; the tests' `syncRun()` clicks and waits for the count to rise, then for "Synced". The labels test also counted the previous page's late sheet request as the labels page's (the duplicate `b=1c` both reviewers saw); it now waits for the plant page to go idle before it starts counting. The bench test was also using a page-level route stub that the service worker's requests bypass after the first load; it routes at the context now. 62 e2e, no retries, six repeats of the labels test clean.
